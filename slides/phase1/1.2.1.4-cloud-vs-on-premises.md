## Two Deployment Models

```
┌─────────────────────────────────────┐
│         UiPath Cloud                │
│  (Hosted by UiPath)                 │
│                                     │
│  ✓ Managed infrastructure           │

│  ✓ Immediate feature access         │
│  ✓ Minimal IT overhead              │
└─────────────────────────────────────┘

┌─────────────────────────────────────┐

│  ✓ Data residency compliance        │
└─────────────────────────────────────┘
```

**Choose based on:** Security requirements, IT capacity, compliance needs

## UiPath Cloud: Overview

**Hosted by UiPath** in the cloud

**Key Characteristics:**
- SaaS model (Software as a Service)
- No infrastructure setup required
- Accessible from anywhere via internet
- Subscription-based pricing
- Part of UiPath Automation Cloud

**URL Format:**
```
https://cloud.uipath.com/{organization}/{tenant}/orchestrator_/
```

---

## UiPath Cloud: Benefits

**Zero Infrastructure Management:**
- No servers to maintain
- No database administration
- No network configuration
- No storage management

**Automatic Updates:**
- Latest features immediately
- Security patches applied automatically
- Zero downtime updates
- No upgrade projects

**Rapid Deployment:**
- Set up in minutes
- No installation required
- Instant scaling
- Global availability

---

## UiPath Cloud: Architecture

```
                     Internet
                        ↓
          ┌─────────────────────────┐
          │   cloud.uipath.com      │
          │  (UiPath-managed)       │
          └─────────────────────────┘
                        ↓
          ┌─────────────────────────┐
          │   Your Organization     │
          │  ├─ Tenant: Dev         │
          │  ├─ Tenant: Staging     │
          │  └─ Tenant: Prod        │
          └─────────────────────────┘
                        ↓
          ┌─────────────────────────┐
          │    Your Robots          │
          │  (Cloud or On-Premises) │
          └─────────────────────────┘
```

Robots can be anywhere—cloud VMs or on-premises machines

---

## UiPath Cloud: Authentication

**Centralized Identity Service:**
- OAuth 2.0 with External Applications
- Centralized user management
- Single sign-on (SSO) available
- Multi-factor authentication (MFA)

**Token Endpoint:**
```
https://cloud.uipath.com/identity_/connect/token
```

**Authentication Flow:**
1. Create External Application in Cloud
2. Get Client ID and Client Secret
3. Request token from identity service
4. Use token for API calls

---

## On-Premises: Overview

**Hosted on your infrastructure**

**Key Characteristics:**
- You manage servers, databases, network
- Installed within your data center
- Full customization and control
- Perpetual or subscription licensing
- Can be air-gapped (no internet)

**URL Format:**
```
https://orchestrator.yourcompany.com/
```
(Your custom domain)

---

## On-Premises: Benefits

**Full Control:**
- Custom security policies
- Network isolation
- Data residency compliance
- Integration with internal systems

**Air-Gapped Deployment:**
- No internet required
- Maximum security
- Meets strict compliance needs
- Complete data isolation

**Customization:**
- Integrate with existing infrastructure
- Custom authentication (AD, SAML, etc.)
- Tailored network configuration
- Specific version control

**Flexible Authentication:**
- Local Orchestrator accounts
- Windows Authentication

- Custom identity providers

**Token Endpoint:**
```
https://orchestrator.yourcompany.com/identity/connect/token
```

## API Endpoint Comparison

**Cloud:**
```python
BASE_URL = 'https://cloud.uipath.com/{org}/{tenant}/orchestrator_'
TOKEN_URL = 'https://cloud.uipath.com/identity_/connect/token'

# Example:
BASE_URL = 'https://cloud.uipath.com/acmecorp/defaulttenant/orchestrator_'
```

**On-Premises:**
```python
BASE_URL = 'https://orchestrator.yourcompany.com'
TOKEN_URL = 'https://orchestrator.yourcompany.com/identity/connect/token'

# Example:
BASE_URL = 'https://orchestrator.acmecorp.com'
```

**Key Difference:** Cloud includes org/tenant in URL path

---

## API URL Structure: Cloud

**Cloud URL Pattern:**
```
https://cloud.uipath.com/{organization}/{tenant}/orchestrator_/odata/{endpoint}
```

**Example:**
```
https://cloud.uipath.com/acmecorp/production/orchestrator_/odata/Robots
```

**Components:**
- `acmecorp` = Organization name
- `production` = Tenant name
- `orchestrator_` = Service (note the underscore)
- `odata/Robots` = API endpoint

---

## API URL Structure: On-Premises

**On-Premises URL Pattern:**
```
https://{your-domain}/odata/{endpoint}
```

**Example:**
```
https://orchestrator.acmecorp.com/odata/Robots
```

**Simpler structure:**
- Your custom domain
- Direct to OData endpoints
- No organization/tenant in URL
- Tenant determined by authentication

## Configuring API Client: Cloud

```python
import os
import requests

# Cloud configuration
CLOUD_CONFIG = {
    'base_url': 'https://cloud.uipath.com/acmecorp/prod/orchestrator_',
    'token_url': 'https://cloud.uipath.com/identity_/connect/token',
    'client_id': os.getenv('CLOUD_CLIENT_ID'),
    'client_secret': os.getenv('CLOUD_CLIENT_SECRET'),
    'scope': 'OR.Robots OR.Jobs OR.Folders'
}

def get_cloud_token(config):
    response = requests.post(config['token_url'], data={
        'grant_type': 'client_credentials',
        'client_id': config['client_id'],
        'client_secret': config['client_secret'],
        'scope': config['scope']
    })
    return response.json()['access_token']
```

## Feature Availability

| Feature | Cloud | On-Premises |
|---------|-------|-------------|
| **Update Timing** | Immediate, automatic | Manual upgrade required |
| **New Features** | First (continuous) | After version release |
| **Feature Flags** | Gradual rollout | All or nothing |
| **Preview Features** | Often available | Usually not |
| **API Versions** | Latest + 2 prior | Depends on version |

**Cloud advantage:** Always latest features

**On-Premises advantage:** Control over upgrade timing

---

## Version Management

**Cloud:**
- Continuous deployment by UiPath
- Always on latest version
- Backward compatibility maintained
- No control over version

**On-Premises:**
- You choose when to upgrade
- Can stay on specific versions
- Test upgrades in dev environment
- Full version control

**Consideration:** Cloud may have features not yet in On-Premises

---

## Network Requirements

**Cloud:**
- ✅ Internet connectivity required
- ✅ HTTPS outbound to cloud.uipath.com
- ✅ Firewall rules for UiPath services
- ❌ Cannot be air-gapped

**On-Premises:**
- ✅ Can be completely air-gapped
- ✅ No internet required (if air-gapped)
- ✅ Full network control
- ⚠️ Internet needed for: updates, telemetry, licensing (optional)

---

## Security and Compliance

**Cloud:**
- UiPath manages security
- SOC 2, ISO 27001 certified
- Data stored in UiPath data centers
- Region selection available
- Good for most compliance needs

**On-Premises:**
- You manage security
- Complete control over data location
- Custom security policies
- Meets strictest compliance (HIPAA, FedRAMP, etc.)
- Required for: air-gapped, data residency laws

**Choose based on:** Compliance requirements, risk tolerance

---

## Data Residency

**Cloud:**
- Data stored in UiPath's cloud regions
- Can choose region (US, EU, Japan, etc.)
- Multi-region options available
- Subject to UiPath's data policies

**On-Premises:**
- Data stays in your data center
- Complete control over location
- Required for some regulations
- Example: German data protection laws, Russian data localization

**Critical for:** Banking, healthcare, government

---

## Management and Maintenance

**Cloud:**
- ✅ Zero maintenance overhead
- ✅ Automatic backups
- ✅ High availability built-in
- ✅ 24/7 UiPath support
- ❌ Less control over downtime

**On-Premises:**
- ❌ You manage everything
- ❌ Manual backups required
- ❌ HA setup is your responsibility
- ❌ Internal IT support needed
- ✅ Full control over maintenance windows

---

## Scalability

**Cloud:**
- Automatic scaling
- No hardware limits
- Pay for what you use
- Global reach instantly

**On-Premises:**
- Manual scaling
- Hardware capacity limits
- Fixed infrastructure costs
- Requires planning and procurement

**Example:** Cloud can handle sudden spike from 10 to 100 robots; On-Premises requires advance planning

---

## Cost Comparison

**Cloud:**
- Subscription per user/robot
- No infrastructure costs
- Predictable monthly expense
- Includes updates and support
- **Good for:** Variable workloads, small-medium deployments

**On-Premises:**
- Perpetual license or subscription
- Infrastructure costs (servers, storage, network)
- IT staff for management
- Maintenance and upgrades
- **Good for:** Large stable deployments, long-term investment

**Break-even point:** Varies by organization (typically 100+ robots)

## Hybrid Deployments

**Combine benefits of both:**

```
┌─────────────────────────────────┐
│      UiPath Cloud               │  ← Management & Orchestration
│   (Orchestrator in Cloud)       │
└─────────────────────────────────┘
            ↓
┌─────────────────────────────────┐
│   Your Data Center              │  ← Robots & Data Processing
│   • Robots (On-Premises)        │
│   • Process sensitive data      │
│   • Connect to Cloud            │
└─────────────────────────────────┘
```

**Use case:** Cloud management, on-premises data processing

---

## Hybrid: How It Works

**Scenario:** Healthcare company with HIPAA requirements

- **Cloud Orchestrator** for:
  - Robot management
  - Job scheduling
  - Monitoring and logging (non-PHI)

- **On-Premises Robots** for:
  - Processing patient data
  - Accessing internal systems
  - Data never leaves network

**Benefit:** Easy management + data security

---

## Hybrid: Implementation

```python
# Cloud Orchestrator configuration
ORCHESTRATOR_URL = 'https://cloud.uipath.com/healthcare/prod/orchestrator_'
TOKEN_URL = 'https://cloud.uipath.com/identity_/connect/token'

# Robots installed on-premises
# Connect to Cloud Orchestrator via internet
# Process data locally, never send to cloud

# API calls go to Cloud
robots_response = requests.get(
    f'{ORCHESTRATOR_URL}/odata/Robots',
    headers={'Authorization': f'Bearer {token}'}
)

# But data processing happens on-premises
# Robots access local databases, files, applications
```

## Choosing: Decision Framework

**Choose Cloud if:**
- ✅ Need quick deployment (days, not months)
- ✅ Want zero infrastructure management
- ✅ Prefer predictable subscription pricing
- ✅ Need latest features immediately
- ✅ Have internet connectivity
- ✅ Standard compliance requirements

**Choose On-Premises if:**
- ✅ Strict data residency requirements
- ✅ Need air-gapped deployment
- ✅ Have IT capacity to manage
- ✅ Want full control over versions
- ✅ Large, stable deployments (100+ robots)
- ✅ Specific compliance mandates (FedRAMP, etc.)

---

## Choosing: Use Case Examples

**Cloud:**
- Startup with no IT infrastructure → **Cloud**
- E-commerce company, global operations → **Cloud**
- Company wants to test RPA → **Cloud** (quick start)

**On-Premises:**
- Bank with data residency laws → **On-Premises**
- Government agency, air-gapped network → **On-Premises**
- Healthcare with HIPAA + PHI → **On-Premises** or **Hybrid**

**Hybrid:**
- Healthcare: Cloud management, on-premises PHI processing → **Hybrid**
- Financial: Cloud for non-sensitive, on-premises for transactions → **Hybrid**

---

## Migration Scenarios

**Cloud to On-Premises:**
- Rare, but possible
- Export processes, assets, queues
- Recreate in On-Premises
- Update robot connections

**On-Premises to Cloud:**
- More common migration path
- UiPath provides migration tools
- Benefits: Reduced IT overhead
- Consideration: Data residency

**Tip:** Test migration in dev environment first

---

## Multi-Environment Strategy

**Common pattern:**

```
Development:   Cloud (easy setup, dev/test)
Staging:       Cloud (pre-production validation)
Production:    On-Premises (compliance, security)
```

**Or:**

```
Development:   Cloud
Staging:       Cloud
Production:    Cloud + On-Premises Robots (Hybrid)
```

**Choose based on:** Security requirements per environment

## API Client: Environment Abstraction

```python
class OrchestratorClient:
    def __init__(self, deployment_type='cloud', **config):
        self.deployment_type = deployment_type
        if deployment_type == 'cloud':
            self.base_url = config['cloud_base_url']
            self.token_url = config['cloud_token_url']
        else:  # on-premises
            self.base_url = config['onprem_base_url']
            self.token_url = config['onprem_token_url']

        self.client_id = config['client_id']
        self.client_secret = config['client_secret']
        self.token = self._get_token()

    def _get_token(self):
        # Same OAuth flow for both
        response = requests.post(self.token_url, data={
            'grant_type': 'client_credentials',
            'client_id': self.client_id,
            'client_secret': self.client_secret'
        })
        return response.json()['access_token']

    def get_robots(self, folder_id):
        # Same API endpoint for both
        response = requests.get(
            f'{self.base_url}/odata/Robots',
            headers={
                'Authorization': f'Bearer {self.token}',
                'X-UIPATH-OrganizationUnitId': str(folder_id)
            }
        )
        return response.json()['value']
```

## Best Practices

**For Both Models:**
- ✅ Use environment variables for configuration
- ✅ Abstract deployment differences in code
- ✅ Test in dev before prod
- ✅ Monitor API usage and errors
- ✅ Follow OAuth best practices

**Cloud-Specific:**
- ✅ Monitor for automatic updates
- ✅ Test integrations after updates
- ✅ Use folder structure effectively

**On-Premises-Specific:**
- ✅ Plan upgrade windows carefully
- ✅ Test upgrades in staging first
- ✅ Backup before upgrades
- ✅ Document custom configurations

## Common Pitfalls

**1. Hard-coding URLs**
```python
# ❌ Bad: Hard-coded for Cloud
BASE_URL = 'https://cloud.uipath.com/acme/prod/orchestrator_'

# ✅ Good: Configurable
BASE_URL = os.getenv('ORCHESTRATOR_URL')
```

**2. Assuming deployment type**
- Always make deployment type explicit
- Use configuration to handle differences
- Don't assume features are identical

**3. Ignoring authentication differences**
- On-Premises may use different auth methods
- Token endpoints may differ
- Test authentication for each deployment

- URL structure (Cloud includes org/tenant)

**Authentication:**
- Both use OAuth 2.0
- Cloud: Centralized UiPath identity
- On-Premises: Flexible (AD, local, SAML, etc.)

**Choosing:**
- Based on: compliance, IT capacity, feature needs
