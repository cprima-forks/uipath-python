## What is Action Center?

**Action Center is UiPath's system for human-in-the-loop automation**

```
┌──────────────────────────────────────┐
│       Automation Workflow            │
│                                      │
│  Process 100 invoices automatically  │
│          ↓                           │
│  5 invoices have unusual amounts     │
│          ↓                           │
│  Create Actions for human review     │
└──────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────┐
│        Action Center                 │
│                                      │
│  Present 5 invoices to manager       │
│  Manager reviews and approves        │
└──────────────────────────────────────┘
                  ↓
┌──────────────────────────────────────┐
│       Automation Continues           │
│                                      │
│  Process approved invoices           │
│  Handle rejected invoices            │
└──────────────────────────────────────┘
```

**Automation + Human Judgment = Better Outcomes**

---

## Why Human-in-the-Loop?

**Not everything can be fully automated**

**Scenarios requiring human input:**
- **Approvals:** Expense over $10,000 needs manager approval
- **Validation:** OCR results uncertain, human validates data
- **Exception Handling:** Automation couldn't process item, human reviews
- **Quality Control:** Spot-check automation results
- **Complex Decisions:** Judgment calls beyond rules-based logic

**Action Center bridges automation and human expertise**

---

## 80/20 Rule

**Common pattern:**

```
1000 invoices to process

800 invoices: Standard, automated fully  ✓
200 invoices: Exceptions, need review    ?
```

**Without Action Center:**
- All 1000 processed manually (slow, expensive)
- Or 200 exceptions block automation (defeats purpose)

**With Action Center:**
- 800 automated (80% straight-through)
- 200 Actions created for human review (20% exceptions)
- Best of both worlds

## What is an Action?

**An Action is a task assigned to a human**

**Components:**
- **Title and Description:** What needs to be done
- **Data:** Information to review (invoice details, document, etc.)
- **Form:** UI with fields for human input
- **Assignment:** Which user(s) should handle it
- **Priority:** High, Normal, Low
- **Deadline:** SLA for completion

**Created by:** Automation workflows
**Completed by:** Humans via Action Center UI or mobile app

## Action States

**Actions flow through states:**

```
1. Unassigned
   ↓ (Assign to user)
2. Pending
   ↓ (User starts working)
3. InProgress
   ↓ (User submits)
4. Completed
```

**Other states:**
- **Canceled:** Action canceled by workflow or admin
- **Expired:** Deadline passed without completion

---

## Action Lifecycle

```
Robot Workflow:
1. Create Action → State: Unassigned
2. Assign to User → State: Pending
3. Wait for completion...

Human User:
1. Receives notification
2. Opens Action in Action Center
3. Reviews data
4. Enters decision in form
5. Submits → State: Completed

Workflow Resumes:
1. Gets Action result (Approved/Rejected, form data)
2. Continues processing based on decision
```

**Synchronous or Asynchronous** based on workflow design

## Creating Actions: Studio Workflow

**Actions are created from UiPath Studio workflows**

**Activities:**
- **Create Form Task:** General-purpose Action with custom form
- **Create Document Validation Action:** For document review/validation
- **Wait for Task Completion:** Waits for human to complete Action

**Example workflow:**
```
1. Process Invoice
2. If Amount > $10,000:
   a. Create Form Task (Invoice Approval)
   b. Wait for Task Completion
   c. If Approved: Continue
   d. If Rejected: Log and skip
3. Else: Process automatically
```

---

## Creating Action: Form Task Activity

**In Studio:**

```
Create Form Task Activity:

Inputs:
- Task Catalog: Select form definition
- Task Title: "Invoice Approval Required"
- Task Data: Invoice details (JSON)
- Assigned To: User/Group/Role
- Priority: High
- Due Date: Now + 24 hours

Output:
- Task ID: For tracking
```

**This creates an Action in Action Center**

---

## Waiting for Completion: Synchronous

**Wait for Task Completion Activity:**

```
Wait for Task Completion:
  Task ID: [from Create Form Task]
  Timeout: 48 hours

Output:
  Action Result: User's decision and form data
  Status: Completed/Expired/Canceled
```

**Workflow suspends until:**
- Human completes Action
- Timeout expires
- Action canceled

**Best for:** Time-sensitive processes where automation waits

---

## Asynchronous Pattern

**Alternative: Don't wait in workflow**

```
Workflow 1 (Producer):
1. Create Form Task
2. End workflow (don't wait)

Action Center:
- Human completes Action at their convenience

Workflow 2 (Consumer):
- Triggered when Action completes (webhook/schedule)
- Retrieves Action result
- Continues processing
```

**Best for:** Long-running approvals where tying up robot is wasteful

## Querying Actions via API

**Actions are accessible via API as TaskItems:**

```
GET /odata/TaskItems
```

**Query capabilities:**
- Filter by Status, Priority, AssignedTo, DueDate
- Get Action details and form data
- Monitor pending Actions
- Build custom dashboards

**API Name:** TaskItems (not "Actions")

---

## Querying: Code Example

```python
def get_pending_actions(base_url, token, folder_id, user_id=None):
    """Get pending Actions, optionally for specific user"""

    params = {
        '$filter': "Status eq 'Pending'"
    }

    if user_id:
        params['$filter'] += f" and AssignedToUserId eq {user_id}"

    response = requests.get(
        f'{base_url}/odata/TaskItems',
        params=params,
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id)
        }
    )

    response.raise_for_status()
    return response.json()['value']

# Usage
pending = get_pending_actions(base_url, token, folder_id)
print(f"Pending Actions: {len(pending)}")
```

## Action Data Structure

**TaskItem fields:**
- **Id:** Unique identifier
- **Title:** Action title
- **Status:** Unassigned, Pending, InProgress, Completed, Expired, Canceled
- **Priority:** High, Normal, Low
- **AssignedToUserId:** Who it's assigned to
- **CreatedTime:** When created
- **DueDate:** Deadline (if set)
- **Data:** Form data (input and output)
- **TaskCatalogId:** Which form template

## Assignment Strategies

**Three ways to assign Actions:**

**1. Specific User:**
```
Assigned To: User ID 123
```
Only that user sees it

**2. Group:**
```
Assigned To: Finance Approvers Group
```
All group members see it; first to claim works on it

**3. Role:**
```
Assigned To: Manager Role
```
All users with that role see it

**Best practice:** Use roles for flexibility

## Priority and Deadlines

**Priority:**
- **High:** Urgent, needs immediate attention
- **Normal:** Standard processing
- **Low:** Can be delayed

**Deadline (SLA):**
- Set when creating Action
- Example: Due in 24 hours, 3 days, 1 week
- If deadline passes → State: Expired

**Escalation:**
- Configure escalation rules
- Example: If not completed in 24h, reassign to senior manager
- Or send reminder notifications

## Monitoring Action Metrics

**Track Action Center performance:**

```python
def get_action_metrics(base_url, token, folder_id):
    """Calculate Action Center metrics"""

    all_actions = get_all_actions(base_url, token, folder_id)

    metrics = {
        'total': len(all_actions),
        'pending': 0,
        'completed': 0,
        'expired': 0,
        'avg_completion_time': 0
    }

    completion_times = []

    for action in all_actions:
        status = action['Status']
        metrics[status.lower()] = metrics.get(status.lower(), 0) + 1

        if status == 'Completed':
            created = datetime.fromisoformat(action['CreatedTime'])
            completed = datetime.fromisoformat(action['CompletedTime'])
            completion_times.append((completed - created).total_seconds())

    if completion_times:
        metrics['avg_completion_time'] = sum(completion_times) / len(completion_times) / 3600  # hours

    return metrics
```

## Best Practices: When to Use Actions

**DO use Action Center for:**
- ✅ Approvals (expense, invoice, leave)
- ✅ Data validation (OCR results, extracted data)
- ✅ Exception handling (items automation couldn't process)
- ✅ Quality checks (spot-check outputs)
- ✅ Complex decisions (requires human judgment)

**DON'T use for:**
- ❌ Routine processing (automate fully instead)
- ❌ High-volume tasks (defeats automation purpose)
- ❌ Time-critical immediate responses (use attended automation)
- ❌ Simple data entry (collect upfront or integrate systems)

**Rule:** Action Center is for exceptions, not the norm

---

## Best Practices: Form Design

**Good form design:**
- Keep forms simple and focused
- Clear labels and instructions
- Use appropriate input types (dropdown vs free text)
- Include relevant data for decision making
- Validation rules to prevent errors
- Mobile-friendly (Action Center has mobile app)

**Bad form design:**
- Too many fields (overwhelming)
- Unclear what's being asked
- Missing context/data
- No validation (garbage in, garbage out)

---

## Best Practices: Assignment

**Assignment guidelines:**
- Use roles/groups, not specific user IDs (flexibility)
- Consider workload distribution
- Set realistic deadlines
- Configure escalation for overdue Actions
- Monitor workload per user/group

**Load balancing:**
- If one group has 100 pending, another has 5 → Reassign
- Use reporting to identify bottlenecks

---

## Best Practices: Integration

**Integrate Actions into workflow design:**

```
Process Flow:
1. Attempt automation
2. If successful → Continue
3. If exception → Create Action
4. Wait for Action (sync) or end (async)
5. Process based on human decision
```

**Log everything:**
- Log Action ID with business transaction
- Enables tracing: "Why was this invoice rejected?" → Check Action

## Action Center vs Attended Automation

**Two models for human involvement:**

| Aspect | Action Center | Attended Automation |
|--------|---------------|---------------------|
| **Timing** | Async (human responds later) | Sync (human present now) |
| **Robot** | Unattended robot | Attended robot on user's desktop |
| **Use Case** | Approvals, reviews | Real-time assistance |
| **Human** | Responds on their schedule | Must be present during execution |
| **Example** | Invoice approval (respond in 24h) | Help user fill complex form now |

**Choose based on:** Can human respond later? → Action Center. Must respond now? → Attended.

## Action Center vs Email Requests

**Why not just send email asking for approval?**

**Email problems:**
- No structured tracking
- No SLA enforcement
- Hard to monitor/report
- Email can be missed/ignored
- No integration with automation

**Action Center benefits:**
- ✅ Structured workflow
- ✅ SLA and escalation
- ✅ Complete tracking and audit trail
- ✅ Seamless automation integration
- ✅ Mobile app for on-the-go responses

**Action Center is built for automation, email is not**

## Limitations and Considerations

**Action Center limitations:**
- Actions created from workflows (not direct API creation)
- Human response time unpredictable
- Requires Action Center license
- Forms must be designed upfront

**Design considerations:**
- What if human never responds? (timeout, escalation)
- What if multiple Actions? (ensure humans aren't overwhelmed)
- How to handle vacation/absence? (reassignment, delegation)
- Training: Humans need to know how to use Action Center
