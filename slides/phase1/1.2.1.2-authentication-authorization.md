## Authentication vs Authorization

**Two different concepts:**

**Authentication** 🔐
- WHO are you?
- Proving your identity
- Username + Password
- Client ID + Client Secret

**Authorization** 🔑
- WHAT can you do?
- Permissions and access rights
- Roles and scopes
- API permissions

**Both are required for secure API access**

---

## Example: Authentication vs Authorization

```
User logs in → Authentication
├── Username: john@example.com
├── Password: secret123
└── Identity confirmed ✓

What can John do? → Authorization
├── Role: Developer
├── Permissions:
│   ├── ✓ Read robots
│   ├── ✓ Create jobs
│   └── ✗ Delete processes (not allowed)
```

**Authentication happens once, authorization checks every action**

---

## Why OAuth 2.0?

**Problems with older methods:**

❌ **Basic Auth**: Send username/password with every request
❌ **API Keys**: Static, long-lived, no expiration
❌ **Shared passwords**: Security nightmare

**OAuth 2.0 solves these:**

✅ Temporary access tokens (expire after 1 hour)
✅ Scoped permissions (request only what you need)
✅ Refresh tokens (get new access without re-auth)
✅ Secure, industry-standard protocol

---

## OAuth 2.0 in UiPath

**UiPath Orchestrator uses OAuth 2.0 for API authentication**

**Key components:**

- **Authorization Server**: UiPath Identity Server
- **Resource Server**: Orchestrator API
- **Client**: Your Python application
- **Access Token**: Temporary credential
- **Refresh Token**: Long-lived credential

**Standard OAuth 2.0 implementation**

---

## OAuth 2.0 Flows

**Different flows for different scenarios:**

**Authorization Code Flow**
- For web applications with user login
- User interacts with browser

**Client Credentials Flow**
- For machine-to-machine (M2M) authentication
- No user interaction
- **This is what we'll use!**

**Implicit Flow**
- For single-page apps (deprecated)

---

## Client Credentials Flow

**Perfect for automated scripts and bots:**

```
Your Application
      │
      │ 1. Request token (client_id + client_secret)
      ↓
UiPath Identity Server
      │
      │ 2. Return access token
      ↓
Your Application
      │
      │ 3. Call API (with access token)
      ↓
Orchestrator API
      │
      │ 4. Return data
      ↓
Your Application
```

**No user interaction needed—fully automated**

## Access Tokens

**Temporary credentials for API access:**

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "OR.Robots OR.Jobs"
}
```

**Key properties:**
- **access_token**: The actual token (JWT format)
- **expires_in**: Lifetime in seconds (usually 3600 = 1 hour)
- **scope**: Permissions granted
- **token_type**: Always "Bearer" for OAuth 2.0

---

## What's Inside an Access Token?

**JWT (JSON Web Token) structure:**

```
Header.Payload.Signature
```

**Payload (decoded):**
```json
{
  "sub": "abc-123-def",
  "scope": "OR.Robots OR.Jobs",
  "iss": "https://cloud.uipath.com/identity",
  "exp": 1699999999,
  "iat": 1699996399
}
```

**Contains:**
- Subject (who)
- Scopes (permissions)
- Issuer (UiPath)
- Expiration time
- Issued at time

---

## Refresh Tokens

**Long-lived credentials to get new access tokens:**

**Why needed?**
- Access tokens expire every hour
- Re-authenticating every hour is annoying
- Refresh tokens enable seamless renewal

**How it works:**
```
Access Token Expires
      ↓
Present Refresh Token
      ↓
Get New Access Token
      ↓
Continue API Calls
```

**Refresh tokens can last days/months**

---

## Token Security

**Access Token:**
- ✅ Short-lived (1 hour)
- ✅ Store in memory only
- ❌ Don't persist to disk
- ❌ Don't commit to git

**Refresh Token:**
- ⚠️  Long-lived
- ⚠️  Can be stored encrypted
- ❌ Never commit to git
- ❌ Never log in plain text

**If compromised, revoke immediately!**

## Scopes (Permissions)

**Scopes define what the token can do:**

**Common UiPath scopes:**
```
OR.Robots        - Read robots
OR.Robots.Write  - Create/update robots
OR.Jobs          - Read jobs
OR.Jobs.Write    - Create jobs
OR.Assets        - Read assets
OR.Assets.Write  - Create/update assets
OR.Queues        - Read queues
OR.Queues.Write  - Add queue items
OR.Administration - Admin operations
```

**Request only what you need!**

---

## Principle of Least Privilege

**Request minimum scopes required:**

```python
# ❌ BAD: Requesting everything
scopes = "OR.Administration"

# ✅ GOOD: Request only what's needed
scopes = "OR.Robots OR.Jobs"
```

**Why?**
- Limits damage if token compromised
- Follows security best practices
- Easier to audit
- Required by many compliance frameworks

## Obtaining an Access Token

**Step-by-step process:**

1. **Prepare credentials**
   - client_id (from External Application)
   - client_secret (from External Application)
   - token_url (UiPath Identity endpoint)

2. **Make POST request**
   - Send credentials to token endpoint
   - Include grant_type and scope

3. **Receive response**
   - Parse access_token
   - Note expires_in
   - Store refresh_token (if provided)

---

## Token Request Example

```python
import requests

token_url = "https://cloud.uipath.com/identity_/connect/token"

data = {
    "grant_type": "client_credentials",
    "client_id": "your-client-id",
    "client_secret": "your-client-secret",
    "scope": "OR.Robots OR.Jobs"
}

response = requests.post(token_url, data=data)
token_data = response.json()

access_token = token_data["access_token"]
expires_in = token_data["expires_in"]
```

**Returns access token valid for 1 hour**

---

## Using the Access Token

**Include in Authorization header:**

```python
import requests

headers = {
    "Authorization": f"Bearer {access_token}",
    "Content-Type": "application/json"
}

response = requests.get(
    "https://cloud.uipath.com/{org}/{tenant}/odata/Robots",
    headers=headers
)

robots = response.json()
```

**Always use Bearer scheme**

---

## Common Mistakes: Token in URL

```python
# ❌ WRONG: Token in URL query string
url = f"https://cloud.uipath.com/api/robots?token={access_token}"

# Problems:
# - URLs get logged everywhere
# - Shows in browser history
# - Not OAuth standard
```

```python
# ✅ CORRECT: Token in Authorization header
headers = {"Authorization": f"Bearer {access_token}"}
response = requests.get(url, headers=headers)
```

**Never put tokens in URLs!**

## Handling Token Expiration

**Access tokens expire after ~1 hour:**

```python
def call_api_with_retry(url, headers):
    response = requests.get(url, headers=headers)

    if response.status_code == 401:
        # Token expired, get new one
        access_token = refresh_access_token()
        headers["Authorization"] = f"Bearer {access_token}"

        # Retry request
        response = requests.get(url, headers=headers)

    return response
```

**Implement automatic token refresh**

## Refresh Token Flow

```python
def refresh_access_token(refresh_token):
    token_url = "https://cloud.uipath.com/identity_/connect/token"

    data = {
        "grant_type": "refresh_token",
        "refresh_token": refresh_token,
        "client_id": "your-client-id",
        "client_secret": "your-client-secret"
    }

    response = requests.post(token_url, data=data)
    token_data = response.json()

    return token_data["access_token"]
```

**Use refresh_token to get new access_token**

## Proactive Token Refresh

**Don't wait for 401—refresh before expiration:**

```python
import time

class TokenManager:
    def __init__(self):
        self.access_token = None
        self.expires_at = 0

    def get_token(self):
        # Check if token expired or expiring soon
        if time.time() >= self.expires_at - 300:  # 5 min buffer
            self.refresh()

        return self.access_token

    def refresh(self):
        # Get new token
        token_data = request_new_token()
        self.access_token = token_data["access_token"]
        self.expires_at = time.time() + token_data["expires_in"]
```

## Role-Based Access Control (RBAC)

**How permissions work in Orchestrator:**

```
Users → Roles → Permissions
```

**Roles** group permissions together:
- **Administrator**: All permissions
- **Developer**: Create/manage processes
- **Robot**: Execute jobs
- **Viewer**: Read-only access

**Users assigned to roles, not individual permissions**

---

## Built-in Roles

**UiPath provides standard roles:**

| Role | Permissions | Use Case |
|------|------------|----------|
| Administrator | Everything | IT admins |
| Automation Developer | Manage processes | Developers |
| Automation User | Execute attended | End users |
| Robot | Execute unattended | Service accounts |
| Tenant Administrator | Tenant settings | Tenant admins |
| Viewer | Read-only | Auditors, managers |

**Can also create custom roles**

---

## Folder-Level Permissions

**Permissions can be folder-specific:**

```
User: john@example.com

Development Folder:
  ├── Role: Administrator
  └── Can do everything in Dev

Production Folder:
  ├── Role: Viewer
  └── Can only read in Prod
```

**Same user, different permissions per folder**

---

## API Permissions vs UI Permissions

**Permissions apply to both:**

**UI Access:**
- What you see in Orchestrator UI
- Based on user's roles

**API Access:**
- What API calls you can make
- Based on token scopes and user roles

**If your user role doesn't allow it, API calls fail even with token**

---

## Checking Permissions

**API returns 403 Forbidden if permission denied:**

```python
response = requests.delete(
    f"{base_url}/odata/Processes({process_id})",
    headers=headers
)

if response.status_code == 403:
    print("Permission denied: Cannot delete processes")
elif response.status_code == 401:
    print("Authentication failed: Token expired or invalid")
elif response.status_code == 200:
    print("Process deleted successfully")
```

**401 = Authentication problem, 403 = Authorization problem**

## Securing Client Secrets

**Client secrets are like passwords:**

```python
# ❌ WRONG: Hard-coded
client_secret = "my-secret-value"

# ❌ WRONG: In source code
API_SECRET = "abc123"

# ✅ CORRECT: Environment variable
client_secret = os.getenv("CLIENT_SECRET")

# ✅ CORRECT: Secret manager
client_secret = get_secret_from_vault("client-secret")
```

**Never commit secrets to git!**

## Token Storage Best Practices

**DO:**
- ✅ Store access tokens in memory
- ✅ Use secure session storage
- ✅ Encrypt if persisting to disk
- ✅ Clear on logout/exit

**DON'T:**
- ❌ Store in plain text files
- ❌ Log tokens
- ❌ Put in error messages
- ❌ Commit to version control

## Logging and Monitoring

**Log authentication events:**

```python
# ✓ Log this
logger.info("Token obtained successfully")
logger.info("Token refreshed")
logger.warning("Authentication failed for client")

# ✗ Don't log this
logger.debug(f"Access token: {access_token}")  # ❌

```

**Log events, not secrets**

## Cross-Tenant Access

**Generally not allowed:**

- Token for Tenant A cannot access Tenant B
- Must authenticate separately per tenant
- Provides isolation and security

**Exception:**
- Organization-level operations
- Requires special permissions

## Common Authentication Errors

**401 Unauthorized:**
- Token expired
- Invalid token
- Missing Authorization header
- Wrong token format

**403 Forbidden:**
- Valid token, insufficient permissions
- Check user roles
- Check scopes

**400 Bad Request:**
- Invalid client credentials
- Wrong token endpoint
- Missing required parameters

```
1. Create External Application in UiPath Cloud
   ↓

   ↓

   ↓
```
