## Why Error Handling Matters

**Reality**: Things go wrong
- Files don't exist
- Network connections fail
- User input is invalid
- API calls timeout
- Data is malformed

**Without error handling**: Your agent crashes
**With error handling**: Your agent recovers gracefully

## The Cost of Unhandled Errors

```python
# ❌ BAD: No error handling
def process_document(file_path):
    with open(file_path) as f:
        data = f.read()
    return data

# What if the file doesn't exist? → Program crashes!
```

```python
# ✅ GOOD: Handles errors
def process_document(file_path):
    try:
        with open(file_path) as f:
            data = f.read()
        return data
    except FileNotFoundError:
        print(f"Error: {file_path} not found")
        return None
```

**Professional agents handle errors gracefully**

## Try-Except Basics

```python
try:
    # Code that might raise an exception
    result = 10 / 0
except ZeroDivisionError:
    # Code that runs if exception occurs
    print("Cannot divide by zero!")

# Program continues normally
print("Execution continues...")
```

**Flow:**
1. Try the code in the `try` block
2. If an exception occurs, jump to matching `except` block
3. Continue with code after try-except

## Catching Specific Exceptions

```python
def convert_to_int(value):
    try:
        return int(value)
    except ValueError:
        print(f"'{value}' is not a valid integer")
        return None

convert_to_int("123")    # Returns 123
convert_to_int("hello")  # Prints error, returns None
```

**Best practice**: Catch specific exceptions, not bare `except`

```python
# ❌ BAD: Catches everything, hides bugs
try:
    code()
except:
    pass

# ✅ GOOD: Catches specific issues
try:
    code()
except ValueError:
    handle_value_error()
```

## Multiple Except Blocks

```python
def read_config(file_path):

        with open(file_path) as f:
```

**Each exception type gets specific handling**

## Catching Multiple Exception Types

```python
# Option 1: Separate except blocks
try:
    process_data()
except ValueError:
    handle_error()
except TypeError:
    handle_error()

# Option 2: Tuple of exceptions (same handling)
try:
    process_data()
except (ValueError, TypeError):
    handle_error()

# Option 3: Using exception variable
try:
    process_data()
except (ValueError, TypeError) as e:
    print(f"Error: {e}")
```

## The Finally Block

```python
file = None
try:
    file = open("data.txt")
    data = file.read()
    process(data)
except FileNotFoundError:
    print("File not found")
except PermissionError:
    print("Permission denied")
finally:
    # ALWAYS runs, even if exception occurred
    if file:
        file.close()
        print("File closed")
```

**Finally** runs whether exception occurred or not

Perfect for cleanup: closing files, network connections, etc.

## Try-Except-Else

```python
try:
    result = calculate_score()
except ValueError:
    print("Calculation error")
    score = 0
else:
    # Runs ONLY if no exception occurred
    print(f"Calculation successful: {result}")
    save_result(result)
finally:
    # Always runs
    log_attempt()
```

**Else**: Runs if try block succeeded (no exception)
**Finally**: Always runs

## Creating Custom Exceptions

```python
class AgentConfigError(Exception):
    """Raised when agent configuration is invalid."""
    pass

class ConfidenceThresholdError(Exception):
    """Raised when confidence threshold is out of range."""
    def __init__(self, threshold):
        self.threshold = threshold
        message = f"Threshold {threshold} must be between 0 and 1"
        super().__init__(message)

# Usage
def set_threshold(value):
    if not (0 <= value <= 1):
        raise ConfidenceThresholdError(value)
    return value
```

## Raising Exceptions

```python
def divide(a, b):
    if b == 0:
        raise ValueError("Division by zero is not allowed")
    return a / b

def process_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    if age > 150:
        raise ValueError("Age seems unrealistic")
    return age

# Using exceptions to enforce contracts
def process_confidence(score):
    if not isinstance(score, (int, float)):
        raise TypeError("Confidence must be a number")
    if not (0.0 <= score <= 1.0):
        raise ValueError("Confidence must be between 0 and 1")
    return score
```

## Re-raising Exceptions

```python
def process_with_logging(data):
    try:
        result = risky_operation(data)
        return result
    except Exception as e:
        # Log the error
        log_error(f"Operation failed: {e}")
        # Re-raise to let caller handle it
        raise

# Caller can still catch and handle
try:
    result = process_with_logging(data)
except ValueError:
    print("Invalid data provided")
```

**Use `raise` without arguments to re-raise current exception**

## Exception Chaining

```python
class DataProcessingError(Exception):
    pass

def process_file(path):
    try:
        with open(path) as f:
            data = json.load(f)
        return process_data(data)
    except FileNotFoundError as e:
        # Chain exceptions to preserve context
        raise DataProcessingError(f"Failed to process {path}") from e
    except json.JSONDecodeError as e:
        raise DataProcessingError(f"Invalid JSON in {path}") from e
```

**Preserves the original exception for debugging**

Shows the full error chain in traceback

## Real-World Example: Agent Input Validation

```python
class InvalidAgentInputError(Exception):
    """Raised when agent input fails validation."""
    pass

def validate_agent_input(user_input):
    """Validate input for document processing agent."""
    if not user_input:
        raise InvalidAgentInputError("Input cannot be empty")

    if not isinstance(user_input, str):
        raise InvalidAgentInputError(
            f"Input must be string, got {type(user_input).__name__}"
        )

    if len(user_input) > 10000:
        raise InvalidAgentInputError(
            f"Input too long: {len(user_input)} chars (max 10000)"
        )

    return user_input.strip()
```

## Real-World Example: Resilient File Processing

```python
def process_documents(file_paths, max_retries=3):
    """Process multiple documents with error handling."""
    results = []
    errors = []

    for path in file_paths:
        retries = 0
        while retries < max_retries:
            try:
                with open(path) as f:
                    data = f.read()
                results.append({"path": path, "data": data})
                break  # Success, exit retry loop

            except FileNotFoundError:
                errors.append({"path": path, "error": "File not found"})
                break  # Don't retry for missing files

            except PermissionError:
                errors.append({"path": path, "error": "Permission denied"})
                break  # Don't retry for permission errors

            except Exception as e:
                retries += 1
                if retries >= max_retries:
                    errors.append({"path": path, "error": str(e)})

    return results, errors
```

## Context Managers and Error Handling

```python
# Context managers automatically handle cleanup
with open("file.txt") as f:
    data = f.read()
# File automatically closed, even if exception occurs

# Equivalent without context manager
f = open("file.txt")
try:
    data = f.read()
finally:
    f.close()  # Must remember to close!
```

**Always use `with` for files and resources**

Guarantees proper cleanup

## Creating Custom Context Managers

```python
from contextlib import contextmanager

@contextmanager
def agent_execution_context(agent_name):
    """Context manager for agent execution."""
    print(f"Starting agent: {agent_name}")
    start_time = time.time()

    try:
        yield  # Agent code runs here
    except Exception as e:
        print(f"Agent {agent_name} failed: {e}")
        raise
    finally:
        duration = time.time() - start_time
        print(f"Agent {agent_name} completed in {duration:.2f}s")

# Usage
with agent_execution_context("DocumentProcessor"):
    process_documents()
```

## Error Handling Best Practices

**DO:**
- ✅ Catch specific exceptions
- ✅ Use finally for cleanup
- ✅ Log errors with context
- ✅ Create custom exceptions for domain errors
- ✅ Provide helpful error messages
- ✅ Use context managers for resources

**DON'T:**
- ❌ Use bare `except:` clauses
- ❌ Silently catch and ignore errors
- ❌ Catch Exception unless re-raising
- ❌ Return different types on error (None vs value)
- ❌ Use exceptions for control flow

## Common Pitfalls

```python
# ❌ Pitfall 1: Bare except catches everything
try:
    code()
except:  # Catches SystemExit, KeyboardInterrupt, etc!
    pass

# ✅ Better: Catch Exception
try:
    code()
except Exception:
    pass

# ❌ Pitfall 2: Silencing errors
try:
    important_operation()
except Exception:
    pass  # Error ignored, no logging!

# ✅ Better: Log before ignoring
try:
    important_operation()
except Exception as e:
    logger.error(f"Operation failed: {e}")
```

## Exception Handling Strategy

```python
def agent_task(input_data):
    """Example of comprehensive error handling strategy."""
    # 1. Validate input early
    try:
        validated_input = validate_input(input_data)
    except ValidationError as e:
        logger.error(f"Invalid input: {e}")
        return {"status": "error", "message": str(e)}

    # 2. Handle specific known errors
    try:
        result = process_data(validated_input)

    except NetworkError as e:
        logger.error(f"Network error: {e}")
        return {"status": "retry", "message": "Network unavailable"}

    except DataError as e:
        logger.error(f"Data error: {e}")
        return {"status": "error", "message": "Invalid data"}

    # 3. Catch unexpected errors
    except Exception as e:
        logger.exception("Unexpected error")
        return {"status": "error", "message": "Internal error"}

    # 4. Return success
    return {"status": "success", "result": result}
```
