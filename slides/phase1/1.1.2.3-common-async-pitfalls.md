## Module 1.1.2.3

Avoiding Mistakes in Asynchronous Python

## Why This Module Matters

**Async code is powerful but tricky**

Common mistakes can:
- Kill performance (blocking the loop)
- Cause subtle bugs (race conditions)
- Lead to deadlocks (improper locking)
- Hide errors (unhandled exceptions)
- Waste resources (memory leaks)

**Learn from others' mistakes before making them yourself!**

---

## Pitfall #1: Blocking the Event Loop

**The #1 mistake in async code**

```python
import time

# ❌ WRONG: Blocks the entire event loop!
async def bad_sleep():
    time.sleep(2)  # Everything stops for 2 seconds
    return "Done"

# ✅ CORRECT: Yields control to event loop
async def good_sleep():
    await asyncio.sleep(2)  # Other tasks can run
    return "Done"
```

**Rule**: Never use synchronous blocking operations in async functions

---

## Common Blocking Operations

```python
# ❌ DON'T USE THESE:
time.sleep()              # Use await asyncio.sleep()
requests.get()            # Use aiohttp
open() / f.read()         # Use aiofiles
socket operations         # Use asyncio socket functions
subprocess.run()          # Use asyncio.create_subprocess_exec()
```

**Why it matters:**

When you block, NO OTHER TASKS can run

The entire event loop freezes

All your concurrent operations become sequential

---

## Identifying Blocking Operations

**Ask yourself:**

1. Does this operation do I/O (files, network, database)?
2. Does it have an async version available?
3. Can I await it?

**If you can't await it, it's probably blocking**

```python
# Can't await? It's blocking!
data = requests.get(url)  # ❌

# Can await? It's non-blocking!
data = await session.get(url)  # ✅
```

---

## Example: The Blocking File Read

```python
# ❌ BAD: Synchronous file I/O blocks
async def process_file_bad(path):
    with open(path) as f:  # Blocks!
        data = f.read()    # Blocks!
    return data

# ✅ GOOD: Async file I/O doesn't block
async def process_file_good(path):
    async with aiofiles.open(path) as f:
        data = await f.read()
    return data
```

**Even "fast" operations like file reads block the loop**

Use async libraries for ALL I/O

## Pitfall #2: Using Wrong Libraries

```python
# ❌ Synchronous libraries (block event loop)
import requests
import sqlite3
import redis

response = requests.get(url)  # Blocks!
```

```python
# ✅ Async libraries (don't block)
import aiohttp
import aiosqlite

response = await session.get(url)  # Yields!
```

**Always check for async versions of libraries**

## Pitfall #3: Forgetting to Await

```python
async def get_data():
    return "data"

# ❌ WRONG: Creates coroutine but doesn't run it
async def main():
    result = get_data()  # Forgot await!
    print(result)  # <coroutine object>

# ✅ CORRECT: Await the coroutine
async def main():
    result = await get_data()
    print(result)  # "data"
```

**Warning**: `RuntimeWarning: coroutine was never awaited`

If you see this, you forgot `await`!

## Pitfall #4: CPU-Bound Work in Async

```python
# ❌ WRONG: Async doesn't help CPU-bound work
async def calculate():
    # Pure computation, no I/O
    result = sum(range(10_000_000))
    return result

# Problem: This blocks the event loop!
# No await points, so no task switching
```

**Async is for I/O-bound work, not CPU-bound**

For CPU-intensive tasks:
- Use `multiprocessing`
- Or run in thread pool: `await asyncio.to_thread(cpu_function)`

---

## When Async Helps vs Doesn't

**Async HELPS with:**
- ✅ Network requests (waiting for response)
- ✅ File I/O (waiting for disk)
- ✅ Database queries (waiting for DB)
- ✅ Multiple concurrent operations

**Async DOESN'T HELP with:**
- ❌ Heavy calculations (no waiting, just computing)
- ❌ CPU-intensive processing
- ❌ Single sequential operation

**Rule**: If there's no waiting/I/O, async won't help

## Pitfall #5: Race Conditions

```python
counter = 0

# ❌ WRONG: Race condition!
async def increment():
    global counter
    temp = counter
    await asyncio.sleep(0.01)  # Task switch happens here
    counter = temp + 1

await asyncio.gather(*[increment() for _ in range(100)])
print(counter)  # Not 100! Maybe 50, maybe 30...
```

**Problem**: Multiple tasks read same value, all increment, all write back

They overwrite each other!

---

## Fixing Race Conditions with Lock

```python
lock = asyncio.Lock()
counter = 0

# ✅ CORRECT: Protected by lock
async def increment():
    global counter
    async with lock:
        # Only one task can be here at a time
        temp = counter
        await asyncio.sleep(0.01)
        counter = temp + 1

await asyncio.gather(*[increment() for _ in range(100)])
print(counter)  # 100 (correct!)
```

**Use asyncio.Lock to protect shared state**

## Pitfall #6: Deadlocks

```python
lock1 = asyncio.Lock()
lock2 = asyncio.Lock()

# ❌ WRONG: Deadlock potential!
async def task_a():
    async with lock1:
        await asyncio.sleep(0.1)
        async with lock2:  # Waits for lock2
            pass

async def task_b():
    async with lock2:
        await asyncio.sleep(0.1)
        async with lock1:  # Waits for lock1
            pass

# Both tasks wait forever!
```

---

## Preventing Deadlocks

**Solution 1: Always acquire locks in the same order**

```python
# ✅ CORRECT: Same order everywhere
async def task_a():
    async with lock1:
        async with lock2:
            pass

async def task_b():
    async with lock1:  # Same order!
        async with lock2:
            pass
```

**Solution 2: Use a single lock**

```python
# ✅ CORRECT: One lock to rule them all
shared_lock = asyncio.Lock()
```

## Pitfall #7: Unhandled Exceptions in Tasks

```python
async def risky_task():
    raise ValueError("Something went wrong!")

# ❌ WRONG: Exception is lost!
async def main():
    task = asyncio.create_task(risky_task())
    # Task fails, but we never know
    await asyncio.sleep(1)

# Task exception is never retrieved!
```

**"Fire and forget" tasks hide errors**

---

## Handling Task Exceptions

```python
# ✅ Solution 1: Await the task
async def main():
    task = asyncio.create_task(risky_task())
    try:
        await task
    except ValueError as e:
        print(f"Task failed: {e}")

# ✅ Solution 2: Use done callback
def handle_exception(task):
    try:
        task.result()
    except Exception as e:
        print(f"Task failed: {e}")

task = asyncio.create_task(risky_task())
task.add_done_callback(handle_exception)
```

## Pitfall #8: Not Canceling Tasks

```python
# ❌ WRONG: Tasks keep running forever!
async def main():
    tasks = [asyncio.create_task(long_task()) for _ in range(10)]

    try:
        await asyncio.wait_for(
            asyncio.gather(*tasks),
            timeout=5.0
        )
    except asyncio.TimeoutError:
        return  # Tasks still running!

# Tasks leak resources, never cleaned up
```

---

## Properly Canceling Tasks

```python
# ✅ CORRECT: Cancel pending tasks
async def main():
    tasks = [asyncio.create_task(long_task()) for _ in range(10)]

    try:
        await asyncio.wait_for(
            asyncio.gather(*tasks),
            timeout=5.0
        )
    except asyncio.TimeoutError:
        # Cancel all tasks
        for task in tasks:
            task.cancel()

        # Wait for cancellation to complete
        await asyncio.gather(*tasks, return_exceptions=True)

    print("All tasks cleaned up")
```

## Pitfall #9: Multiple asyncio.run() Calls

```python
# ❌ WRONG: Can't call asyncio.run() twice!
async def task1():
    return "Result 1"

async def task2():
    return "Result 2"

result1 = asyncio.run(task1())  # OK
result2 = asyncio.run(task2())  # ERROR!

# RuntimeError: asyncio.run() cannot be called from a running event loop
```

**asyncio.run() closes the event loop when done**

Can't reuse a closed loop

---

## Single Entry Point Pattern

```python
# ✅ CORRECT: One main() function
async def task1():
    return "Result 1"

async def task2():
    return "Result 2"

async def main():
    result1 = await task1()
    result2 = await task2()
    return result1, result2

# Single entry point
results = asyncio.run(main())
```

**Create one async main() and call everything from there**

## Pitfall #10: Mixing Sync and Async

```python
# ❌ WRONG: Can't use await in regular function
def sync_function():
    result = await async_function()  # SyntaxError!
    return result

# ❌ WRONG: Can't call async function directly
def sync_function():
    result = async_function()  # Returns coroutine, doesn't run
    return result
```

**You can't mix sync and async freely**

---

## Calling Async from Sync

```python
# ✅ Solution 1: Make function async
async def async_function():
    result = await async_function()
    return result

# ✅ Solution 2: Use asyncio.run()
def sync_function():
    result = asyncio.run(async_function())
    return result

# ✅ Solution 3: Use existing event loop
def sync_function():
    loop = asyncio.get_event_loop()
    result = loop.run_until_complete(async_function())
    return result
```

## Pitfall #11: Resource Leaks

```python
# ❌ WRONG: Session never closed!
async def fetch_data():
    session = aiohttp.ClientSession()
    data = await session.get(url)
    return data
# Session leaked!

# ✅ CORRECT: Use context manager
async def fetch_data():
    async with aiohttp.ClientSession() as session:
        data = await session.get(url)
        return data
# Session automatically closed
```

**Always use `async with` for async resources**

---

## Common Resource Leaks

**Watch out for:**
- HTTP sessions (aiohttp.ClientSession)
- Database connections
- File handles (even with aiofiles)
- Locks held too long
- Tasks never awaited or cancelled

**Solution**: Always use context managers

```python
async with resource:
    # Use resource
# Automatically cleaned up
```

## Debugging Async Code

**Enable debug mode:**

```python
# Method 1: In code
asyncio.run(main(), debug=True)

# Method 2: Environment variable
# PYTHONASYNCIODEBUG=1

# Method 3: Set event loop debug
loop = asyncio.get_event_loop()
loop.set_debug(True)
```

**Debug mode shows:**
- Coroutines that were never awaited
- Tasks that take too long
- Tasks destroyed while pending

## Common Debug Warnings

**"coroutine was never awaited"**
```python
async def task():
    return 42

result = task()  # Forgot await!
```

**"Task was destroyed but it is pending!"**
```python
task = asyncio.create_task(long_task())

```

**"Executing took X.XX seconds"**
```python
# A callback or coroutine took too long

```

## Debugging Techniques

**1. Add logging**
```python
import logging
logging.basicConfig(level=logging.DEBUG)
```

**2. Print task status**
```python
print(f"Task done: {task.done()}")
print(f"Task cancelled: {task.cancelled()}")
```

**3. Use asyncio.all_tasks()**
```python
tasks = asyncio.all_tasks()
print(f"Running tasks: {len(tasks)}")
for task in tasks:
    print(task.get_coro())
```

**4. Check for blocking with profiling**
```python
import cProfile
cProfile.run('asyncio.run(main())')
```

## Best Practices Summary

**DO:**
- ✅ Use async libraries (aiohttp, aiofiles, asyncpg)
- ✅ Always await coroutines
- ✅ Protect shared state with Lock
- ✅ Cancel tasks you don't need
- ✅ Use context managers for resources
- ✅ Handle exceptions in background tasks
- ✅ Enable debug mode during development

**DON'T:**
- ❌ Use synchronous blocking operations
- ❌ Forget to await
- ❌ Use async for CPU-bound work
- ❌ Create race conditions
- ❌ Leave tasks running forever
- ❌ Call asyncio.run() multiple times

## Checklist: Is Your Async Code Correct?

**Before deploying, check:**

5. ☑ Resources cleaned up with context managers
6. ☑ Exceptions handled in background tasks
7. ☑ No CPU-bound work in async functions

## Performance Anti-Patterns

**Anti-Pattern 1: Too much concurrency**
```python
# ❌ Creates 10,000 connections!
await asyncio.gather(*[fetch(url) for url in urls])

# ✅ Limit concurrency
semaphore = asyncio.Semaphore(10)
```

**Anti-Pattern 2: No timeouts**
```python
# ❌ Waits forever
await fetch_data()

# ✅ Set timeout
await asyncio.wait_for(fetch_data(), timeout=5.0)
```

## Real-World Example: Fixing Broken Code

**Before (broken):**
```python
async def process_documents(paths):
    results = []
    for path in paths:
        with open(path) as f:  # ❌ Blocking!
            data = f.read()
        results.append(data)
    return results
```

**After (fixed):**
```python
async def process_documents(paths):
    async def process_one(path):
        async with aiofiles.open(path) as f:  # ✅ Non-blocking
            return await f.read()

    return await asyncio.gather(*[process_one(p) for p in paths])
```

## Real-World Example: Adding Error Handling

**Before (loses errors):**
```python
async def fetch_all(urls):
    tasks = [fetch_url(url) for url in urls]
    return await asyncio.gather(*tasks)  # ❌ First error stops everything
```

**After (handles errors):**
```python
async def fetch_all(urls):
    tasks = [fetch_url(url) for url in urls]
    results = await asyncio.gather(*tasks, return_exceptions=True)

    successes = [r for r in results if not isinstance(r, Exception)]
    failures = [r for r in results if isinstance(r, Exception)]

    print(f"Success: {len(successes)}, Failed: {len(failures)}")
    return successes
```

## Common Async Patterns

**Pattern 1: Retry with exponential backoff**
```python
async def fetch_with_retry(url, max_retries=3):
    for attempt in range(max_retries):
        try:
            return await fetch(url)
        except Exception as e:
            if attempt == max_retries - 1:
                raise
            await asyncio.sleep(2 ** attempt)
```

**Pattern 2: Timeout all operations**
```python
async with asyncio.timeout(10.0):
    results = await process_batch()
```
