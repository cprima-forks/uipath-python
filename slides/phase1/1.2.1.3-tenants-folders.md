## The Three-Level Hierarchy

```
┌─────────────────────────────────────┐
│         Organization                │  ← Billing & Subscription
│  (e.g., Acme Corporation)          │
├─────────────────────────────────────┤
│  ┌──────────────┐ ┌──────────────┐│
│  │  Tenant: Dev │ │ Tenant: Prod ││  ← Isolated Workspaces
│  └──────────────┘ └──────────────┘│
│        │                │          │
│   ┌────┴────┐      ┌────┴────┐   │
│   │ Finance │      │ Finance │   │  ← Resource Grouping
│   │   HR    │      │   HR    │   │
│   │   IT    │      │   IT    │   │
│   └─────────┘      └─────────┘   │
│     (Folders)        (Folders)    │
└─────────────────────────────────────┘
```

**Organization → Tenant → Folder**

---

## What is an Organization?

**Top level** of the hierarchy

**Purpose:**
- Billing and subscription management
- License allocation
- Organization-wide settings
- User management across tenants

**Example:** Your company "Acme Corporation" is an Organization

---

## What is a Tenant?

**Isolated workspace** for automation resources

**Characteristics:**
- Complete data isolation
- Independent user management
- Separate security policies
- Own set of resources (robots, processes, queues)

**Think of it as:** A completely separate Orchestrator instance within your Organization

---

## Tenant Use Cases

**1. Environment Separation**
```
Organization: Acme Corp
├─ Tenant: Development
├─ Tenant: Staging
└─ Tenant: Production
```

**2. Business Unit Separation**
```
Organization: Acme Corp
├─ Tenant: Finance
├─ Tenant: HR
└─ Tenant: Operations
```

**3. Customer Separation** (for MSPs)
```
Organization: RPA Services Inc
├─ Tenant: Client A
├─ Tenant: Client B
└─ Tenant: Client C
```

---

## What is a Folder?

**Resource grouping** within a tenant

**Characteristics:**
- Organizes robots, processes, queues, assets
- Role-based permissions
- Can be nested (Modern folders)
- Isolated from other folders

**Think of it as:** Departments or teams within a workspace

---

## Folder Use Cases

**Within a Production Tenant:**
```
Tenant: Production
├─ Folder: Finance
│  ├─ Invoice Processing robots
│  ├─ Invoice Processing process
│  └─ Invoice Queue
├─ Folder: HR
│  ├─ Onboarding robots
│  └─ Employee Data assets
└─ Folder: IT
   ├─ Helpdesk robots
   └─ Ticket Queue
```

Each folder has different teams with different permissions

---

## The Complete Hierarchy

```
Organization (Billing)
    ↓
Tenant (Isolation)
    ↓
Folder (Organization)
    ↓
Resources (Robots, Processes, Queues, Assets)
```

**Example:**
- Organization: Acme Corp
- Tenant: Production
- Folder: Finance
- Resources: 5 robots, 3 processes, 2 queues

---

## Tenant Isolation

Tenants are **completely isolated**:

**Separate:**
- Users and permissions
- Data and databases
- Robots and processes
- Queues and assets
- Audit logs
- Settings and configurations

**No cross-tenant access** without separate credentials

---

## Multi-Tenancy Benefits

**Security:**
- Complete data isolation
- Independent security policies
- Separate audit trails

**Organization:**
- Clear environment boundaries (Dev/Staging/Prod)
- Business unit independence
- Customer separation

**Management:**
- Independent resource allocation
- Different administrators per tenant
- Isolated testing and deployment

---

## Folder Permissions

Folders use **Role-Based Access Control (RBAC)**

**Common Roles:**
- **Admin:** Full control over folder
- **Edit:** Can modify resources
- **View:** Read-only access
- **Custom roles:** Specific permissions

**User can have different roles in different folders:**
- Admin in Finance folder
- View in HR folder
- No access to IT folder

---

## Folder Permission Example

```python
# Alice's permissions:
Finance folder: Admin (full control)
HR folder: View (read-only)
IT folder: No access

# API behavior:
# Alice calls /odata/Robots with Finance folder context
# → Success, can see all robots

# Alice calls /odata/Robots with IT folder context
# → Error: Forbidden (no access)
```

## Using Folder Context in API Calls

**Critical:** Always specify which folder you're accessing

**Method:** Use the `X-UIPATH-OrganizationUnitId` header

```python
headers = {
    'Authorization': f'Bearer {access_token}',
    'X-UIPATH-OrganizationUnitId': '12345'  # Folder ID
}

response = requests.get(
    'https://cloud.uipath.com/org/tenant/orchestrator_/odata/Robots',
    headers=headers
)
```

**Without this header:** Request may fail or access wrong folder

## Getting Folder IDs

**Use the Folders endpoint:**

```python
# Get all folders
response = requests.get(
    f'{base_url}/odata/Folders',
    headers={'Authorization': f'Bearer {token}'}
)

folders = response.json()['value']

# Find specific folder
finance_folder = next(
    f for f in folders
    if f['DisplayName'] == 'Finance'
)

folder_id = finance_folder['Id']  # Use this in API calls
```

## Modern vs Classic Folders

**Two folder types** in Orchestrator:

| Feature | Classic Folders | Modern Folders |
|---------|----------------|----------------|
| **Permissions** | Basic (Admin/User) | Granular RBAC |
| **Inheritance** | No | Yes |
| **Nesting** | Limited | Full hierarchy |
| **Introduced** | Pre-2020.10 | 2020.10+ |
| **Recommendation** | Legacy | New deployments |

**Modern folders** are the recommended approach

---

## Modern Folder Features

**Granular Permissions:**
- Many built-in roles
- Custom role creation
- Specific permission control

**Folder Hierarchy:**
- Parent and child folders
- Permission inheritance
- Organized structure

**Better Access Control:**
- User groups
- Detailed audit logs
- Fine-grained security

## Best Practices: Tenant Strategy

**Use tenants for:**
- ✅ Environment separation (Dev, Staging, Prod)
- ✅ Complete data isolation needs
- ✅ Different security policies
- ✅ Customer/client separation (MSPs)

**Don't use tenants for:**
- ❌ Simple resource grouping (use folders)
- ❌ Team separation within same environment
- ❌ Temporary projects

**Rule of thumb:** Tenants for isolation, Folders for organization

---

## Best Practices: Folder Strategy

**Use folders for:**
- ✅ Department/team separation
- ✅ Project grouping
- ✅ Access control within a tenant
- ✅ Resource organization

**Folder naming:**
- Use clear, descriptive names
- Follow consistent naming convention
- Consider hierarchy for Modern folders

**Example:**
```
Finance
Finance-Invoicing
Finance-Reporting
HR
HR-Onboarding
HR-Offboarding
```

---

## Best Practices: Permission Management

**Principle of least privilege:**
- Give users minimum permissions needed
- Use View role for monitoring
- Restrict Admin role to leaders
- Audit permissions regularly

**Example:**
```
Finance Manager: Admin on Finance folder
Finance Developer: Edit on Finance folder
Finance Analyst: View on Finance folder
CEO: View on all folders
```

## Best Practices: API Development

**Always include folder context:**

```python
# ✅ Good: Always specify folder
headers = {
    'Authorization': f'Bearer {token}',
    'X-UIPATH-OrganizationUnitId': folder_id
}

# ❌ Bad: Missing folder context
headers = {
    'Authorization': f'Bearer {token}'
}
```

**Cache folder IDs:**
- Lookup folders at startup
- Store folder IDs for reuse
- Don't query folders on every API call

---

## Common Pitfall #1: Missing Folder Context

**Problem:**
```python
# Missing X-UIPATH-OrganizationUnitId header
response = requests.get(
    f'{base_url}/odata/Robots',
    headers={'Authorization': f'Bearer {token}'}
)
# May return error or unexpected results
```

**Solution:**
```python
# Always include folder context
response = requests.get(
    f'{base_url}/odata/Robots',
    headers={
        'Authorization': f'Bearer {token}',
        'X-UIPATH-OrganizationUnitId': folder_id
    }
)
```

---

## Common Pitfall #2: Hard-coding Folder IDs

**Problem:**
```python
# ❌ Don't hard-code folder IDs
FOLDER_ID = '12345'  # Breaks if folder is recreated
```

**Solution:**
```python
# ✅ Lookup folder by name
def get_folder_id(base_url, token, folder_name):
    response = requests.get(
        f'{base_url}/odata/Folders',
        headers={'Authorization': f'Bearer {token}'},
        params={'$filter': f"DisplayName eq '{folder_name}'"}
    )
    folders = response.json()['value']
    if not folders:
        raise ValueError(f"Folder '{folder_name}' not found")
    return folders[0]['Id']

folder_id = get_folder_id(base_url, token, 'Finance')
```

## Common Pitfall #3: Tenant Confusion

**Problem:**
- Using wrong tenant credentials
- Expecting resources from one tenant in another
- Confusion about which tenant you're accessing

**Solution:**
- Use clear credential naming: `DEV_CLIENT_ID`, `PROD_CLIENT_ID`
- Log which tenant you're authenticated to
- Keep tenant contexts separate in code
- Use environment variables per tenant

## Hands-on Example: Multi-Tenant Setup

```python
import os
import requests

class OrchestratorClient:
    def __init__(self, tenant_name, base_url, client_id, client_secret):
        self.tenant_name = tenant_name
        self.base_url = base_url
        self.token = self._get_token(client_id, client_secret)
        self.folders = self._get_folders()

    def _get_token(self, client_id, client_secret):
        # OAuth implementation
        pass

    def _get_folders(self):
        response = requests.get(
            f'{self.base_url}/odata/Folders',
            headers={'Authorization': f'Bearer {self.token}'}
        )
        return {f['DisplayName']: f['Id']
                for f in response.json()['value']}

    def get_robots(self, folder_name):
        folder_id = self.folders[folder_name]
        response = requests.get(
            f'{self.base_url}/odata/Robots',
            headers={
                'Authorization': f'Bearer {self.token}',
                'X-UIPATH-OrganizationUnitId': str(folder_id)
            }
        )
        return response.json()['value']

# Usage
dev = OrchestratorClient('Development', dev_url, dev_id, dev_secret)
prod = OrchestratorClient('Production', prod_url, prod_id, prod_secret)

dev_finance_robots = dev.get_robots('Finance')
prod_finance_robots = prod.get_robots('Finance')
```
