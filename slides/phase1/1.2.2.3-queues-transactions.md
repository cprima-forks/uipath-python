## What Are Queues?

**A Queue is a container for work items that need to be processed**

```
┌────────────────────────────────┐
│    Invoice Processing Queue    │
├────────────────────────────────┤
│ Item 1: Invoice INV-001        │
│ Item 2: Invoice INV-002        │
│ Item 3: Invoice INV-003        │
│ ...                            │
│ Item 500: Invoice INV-500      │
└────────────────────────────────┘
         ↓  ↓  ↓
    Robot 1  Robot 2  Robot 3
```

**Think of it as:** A to-do list that multiple robots can work from simultaneously

---

## Why Use Queues?

**Without Queues:**
- Process all items in one job (single point of failure)
- Hard to distribute work across robots
- If job fails midway, lose progress
- Difficult to track what's done vs pending

**With Queues:**
- **Distributed**: Multiple robots process in parallel
- **Fault-tolerant**: If one robot fails, others continue
- **Progress tracking**: See what's processed, what's pending
- **Priority handling**: Urgent items processed first
- **Automatic retry**: Failed items can be retried

**Queues = Scalability + Resilience**

## Queue Items

**A Queue Item = One unit of work**

**Contains:**
- **SpecificContent:** The actual data (JSON)
- **Reference:** Optional human-readable ID
- **Priority:** High, Normal, Low
- **Status:** New, InProgress, Successful, Failed, etc.
- **Timestamps:** Creation time, start time, end time
- **Retry info:** Retry number, max retries

**Example:** In "InvoiceQueue", each item represents one invoice to process

---

## Transaction Lifecycle

```
1. Item Created (Status: New)
        ↓
2. Robot Gets Item (Status: InProgress)
        ↓
3. Robot Processes
        ↓
4. Result Set:
   • Successful ✓
   • Failed (Business Exception) ✗
   • Failed (Application Exception) → Back to New (Retry)
```

**Transactions ensure:** Exactly-once processing, fault tolerance, progress tracking

---

## Transaction States

| State | Meaning | Can Retry? |
|-------|---------|------------|
| **New** | Not yet processed | N/A |
| **InProgress** | Currently being processed | N/A |
| **Successful** | Completed successfully | No |
| **Failed** | Business exception (data error) | No |
| **Abandoned** | Robot disconnected mid-processing | Yes (auto) |
| **Retried** | Was retried after app exception | Depends |

**Key distinction:** Failed (permanent) vs Retry (transient error)

## Adding Items: API Endpoint

**Add a single item:**

```
POST /odata/Queues/UiPathODataSvc.AddQueueItem
```

**Payload structure:**
```json
{
  "itemData": {
    "Name": "InvoiceQueue",
    "SpecificContent": {
      "InvoiceID": "INV-001",
      "Amount": 1500,
      "CustomerID": "C123"
    },
    "Reference": "INV-001",
    "Priority": "Normal"
  }
}
```

**Returns:** Created queue item with ID and status

---

## Adding Items: Code Example

```python
def add_queue_item(base_url, token, folder_id, queue_name, content, reference=None, priority='Normal'):
    """Add a single item to queue"""

    payload = {
        "itemData": {
            "Name": queue_name,
            "SpecificContent": content,
            "Priority": priority
        }
    }

    if reference:
        payload["itemData"]["Reference"] = reference

    response = requests.post(
        f'{base_url}/odata/Queues/UiPathODataSvc.AddQueueItem',
        json=payload,
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id),
            'Content-Type': 'application/json'
        }
    )

    response.raise_for_status()
    return response.json()
```

## Reference Field

**Reference = Optional human-readable identifier**

**Use cases:**
- Track by business ID (invoice number, order ID)
- Search for specific items
- Display in reports

**Example:**
```python
# With reference
add_queue_item(..., content={...}, reference='INV-001')

```

**Best practice:** Always set Reference for traceability

## Priority

**Three priority levels:**

- **High:** Processed first
- **Normal:** Default
- **Low:** Processed last

**Within same priority:** FIFO (first in, first out)

**Use cases:**
- Expedited orders → High
- Regular processing → Normal
- Batch cleanup → Low

```python
add_queue_item(..., priority='High')  # Urgent
add_queue_item(..., priority='Normal')  # Default
add_queue_item(..., priority='Low')  # Background
```

## Bulk Adding Items

**For multiple items, use BulkAddQueueItems:**

```
POST /odata/Queues/UiPathODataSvc.BulkAddQueueItems
```

**Supports up to 100 items per call**

```python
def bulk_add_items(base_url, token, folder_id, queue_name, items_data):
    """Add multiple items in one call"""

    queue_items = [
        {
            "Name": queue_name,
            "SpecificContent": content,
            "Reference": ref,
            "Priority": priority
        }
        for content, ref, priority in items_data
    ]

    payload = {"queueItems": queue_items}

    response = requests.post(
        f'{base_url}/odata/Queues/UiPathODataSvc.BulkAddQueueItems',
        json=payload,
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id),
            'Content-Type': 'application/json'
        }
    )

    response.raise_for_status()
    return response.json()
```

---

## Bulk Adding: Usage

```python
# Prepare 500 invoices
invoices = [
    ({'InvoiceID': f'INV-{i:03d}', 'Amount': 1000+i}, f'INV-{i:03d}', 'Normal')
    for i in range(1, 501)
]

# Add in batches of 100
for i in range(0, len(invoices), 100):
    batch = invoices[i:i+100]
    result = bulk_add_items(base_url, token, folder_id, 'InvoiceQueue', batch)
    print(f"Added batch {i//100 + 1}: {len(batch)} items")

# Result: 500 items in queue, ready for processing
```

**Much faster than 500 individual API calls**

## Processing Items: StartTransaction

**To get the next item to process:**

```
POST /odata/Queues/UiPathODataSvc.StartTransaction
```

**What it does:**
1. Finds next "New" item (by priority, then FIFO)
2. Marks it "InProgress"
3. Assigns it to robot
4. Returns the item

**Atomic operation:** Prevents race conditions with multiple robots

---

## StartTransaction: Code Example

```python
def start_transaction(base_url, token, folder_id, queue_name, robot_identifier='PythonWorker'):
    """Get next queue item to process"""

    payload = {
        "transactionData": {
            "Name": queue_name,
            "RobotIdentifier": robot_identifier
        }
    }

    response = requests.post(
        f'{base_url}/odata/Queues/UiPathODataSvc.StartTransaction',
        json=payload,
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id),
            'Content-Type': 'application/json'
        }
    )

    response.raise_for_status()
    result = response.json()

    # Returns None if no items available
    return result.get('value')
```

---

## Processing Loop

```python
while True:
    # Get next item
    item = start_transaction(base_url, token, folder_id, 'InvoiceQueue')

    if not item:
        print("No more items in queue")
        break

    print(f"Processing item {item['Reference']}")

    try:
        # Extract data
        data = json.loads(item['SpecificContent'])

        # Process the work
        result = process_invoice(data)

        # Mark as successful
        set_transaction_result(
            base_url, token, folder_id,
            item['Id'], 'Successful',
            output_data={'Result': result}
        )

    except Exception as e:
        # Mark as failed
        set_transaction_result(
            base_url, token, folder_id,
            item['Id'], 'Failed',
            error_message=str(e)
        )
```

## SetTransactionResult: Code

```python
def set_transaction_result(base_url, token, folder_id, item_id, status, output_data=None, error_message=None):
    """Set result of processed transaction"""

    payload = {
        "transactionData": {
            "QueueItemId": item_id,
            "Status": status
        }
    }

    if output_data:
        payload["transactionData"]["OutputData"] = output_data

    if error_message:
        payload["transactionData"]["ProcessingException"] = {
            "Reason": error_message,
            "Type": "BusinessException"  # or "ApplicationException"
        }

    response = requests.post(
        f'{base_url}/odata/Queues/UiPathODataSvc.SetTransactionResult',
        json=payload,
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id),
            'Content-Type': 'application/json'
        }
    )

    response.raise_for_status()
    return response.json()
```

## Business vs Application Exceptions

**Two types of failures:**

**Business Exception:**
- Expected data error
- Example: Invalid invoice number, missing customer
- Item marked "Failed" permanently
- **No automatic retry**

**Application Exception:**
- Unexpected technical error
- Example: Database down, network timeout, system crash
- Item goes back to "New" for retry
- **Automatic retry** (up to MaxRetryNumber)

**Choose correctly:** Prevents infinite retries on bad data

---

## Exception Handling Example

```python
def process_queue_item(item):
    """Process with proper exception handling"""

    data = json.loads(item['SpecificContent'])

    try:
        # Validate data
        if not data.get('InvoiceID'):
            raise BusinessException("Missing InvoiceID")

        # Process
        result = call_external_api(data)

        return 'Successful', {'Result': result}

    except BusinessException as e:
        # Data error - don't retry
        return 'Failed', None, str(e), 'BusinessException'

    except (NetworkError, TimeoutError) as e:
        # Technical error - will retry
        return 'Failed', None, str(e), 'ApplicationException'
```

---

## Retry Mechanism

**How Application Exceptions trigger retries:**

```
1. Item processing fails with ApplicationException
        ↓
2. Item status: InProgress → New
3. RetryNumber increments (0 → 1)
        ↓
4. Item available for processing again
        ↓
5. Another robot (or same robot) picks it up
        ↓
If RetryNumber >= MaxRetryNumber:
   Item marked "Failed" (no more retries)
```

**MaxRetryNumber** is configured per queue (default: 1)

## Monitoring Queues

**Get queue statistics:**

```python
def get_queue_stats(base_url, token, folder_id, queue_name):
    """Get current queue statistics"""

    # Get queue definition
    response = requests.get(
        f'{base_url}/odata/QueueDefinitions',
        params={'$filter': f"Name eq '{queue_name}'"},
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id)
        }
    )

    queue = response.json()['value'][0]

    return {
        'MaxRetries': queue['MaxNumberOfRetries'],
        'AcceptAutomaticallyRetry': queue['AcceptAutomaticallyRetry']
    }
```

## Monitoring Item Counts

```python
def get_queue_item_counts(base_url, token, folder_id, queue_name):
    """Count items by status"""

    counts = {}

    for status in ['New', 'InProgress', 'Successful', 'Failed']:
        response = requests.get(
            f'{base_url}/odata/QueueItems/$count',
            params={
                '$filter': f"QueueDefinitionId eq {queue_id} and Status eq '{status}'"
            },
            headers={
                'Authorization': f'Bearer {token}',
                'X-UIPATH-OrganizationUnitId': str(folder_id)
            }
        )

        counts[status] = int(response.text)

    return counts

# Usage
counts = get_queue_item_counts(...)

print(f"Processing: {counts['InProgress']}")
print(f"Completed: {counts['Successful']}")
print(f"Failed: {counts['Failed']}")
```

## Progress Calculation

```python
def calculate_progress(counts):
    """Calculate processing progress"""

    total = sum(counts.values())
    if total == 0:
        return 100.0

    completed = counts['Successful'] + counts['Failed']
    progress = (completed / total) * 100

    return {
        'total': total,
        'completed': completed,
        'pending': counts['New'],
        'in_progress': counts['InProgress'],
        'successful': counts['Successful'],
        'failed': counts['Failed'],
        'progress_pct': progress,
        'success_rate': (counts['Successful'] / completed * 100) if completed > 0 else 0
    }

# Usage
stats = calculate_progress(counts)
print(f"Progress: {stats['progress_pct']:.1f}%")
print(f"Success Rate: {stats['success_rate']:.1f}%")
```

## Distributed Processing Pattern

**The standard pattern:**

```python
# Producer: Add items to queue
for invoice in invoices:
    add_queue_item(queue_name, content={'InvoiceID': invoice.id})

# Consumers: Multiple robots process in parallel
# Robot 1, 2, 3, ... all run this:
while True:
    item = start_transaction(queue_name)
    if not item:
        break

    # Process
    result = process(item)

    # Set result
    set_transaction_result(item['Id'], 'Successful')
```

**Benefits:** Load balancing, fault tolerance, scalability

## Complete Example: Producer

```python
def load_queue(base_url, token, folder_id, queue_name, invoices):
    """Load invoices into queue"""

    print(f"Loading {len(invoices)} invoices...")

    # Prepare items
    items_data = [
        (
            {'InvoiceID': inv.id, 'Amount': inv.amount, 'CustomerID': inv.customer_id},
            inv.id,  # Reference
            'High' if inv.amount > 10000 else 'Normal'  # Priority
        )
        for inv in invoices
    ]

    # Add in batches of 100
    for i in range(0, len(items_data), 100):
        batch = items_data[i:i+100]
        bulk_add_items(base_url, token, folder_id, queue_name, batch)
        print(f"  Loaded batch {i//100 + 1}")

    print("Queue loaded successfully!")
```

## Complete Example: Consumer

```python
def process_queue(base_url, token, folder_id, queue_name, worker_id):
    """Process items from queue"""

    processed = 0
    failed = 0

    while True:
        # Get next item
        item = start_transaction(base_url, token, folder_id, queue_name, worker_id)

        if not item:
            print("No more items")
            break

        # Process
        try:
            data = json.loads(item['SpecificContent'])
            result = process_invoice(data)

            set_transaction_result(
                base_url, token, folder_id,
                item['Id'], 'Successful',
                output_data={'Result': result}
            )
            processed += 1

        except Exception as e:
            set_transaction_result(
                base_url, token, folder_id,
                item['Id'], 'Failed',
                error_message=str(e)
            )
            failed += 1

        if (processed + failed) % 10 == 0:
            print(f"Processed: {processed}, Failed: {failed}")

    print(f"Done. Processed: {processed}, Failed: {failed}")
```

## Multi-Worker Pattern

```python
import concurrent.futures

# Start multiple workers in parallel
with concurrent.futures.ThreadPoolExecutor(max_workers=5) as executor:
    futures = [
        executor.submit(
            process_queue,
            base_url, token, folder_id, 'InvoiceQueue',
            worker_id=f'Worker-{i}'
        )
        for i in range(1, 6)  # 5 workers
    ]

    # Wait for all to complete
    concurrent.futures.wait(futures)

print("All workers finished!")
```

**Result:** 5 parallel workers processing from the same queue

## Best Practices: Queue Design

**1. Granularity**
- One queue item = One logical unit of work
- Not too large (avoid long transactions)
- Not too small (avoid excessive overhead)

**2. Data in SpecificContent**
- Include all data needed for processing
- Or include references to retrieve data
- Keep size reasonable (<1 MB)

**3. Reference field**
- Always set for traceability
- Use business identifiers (invoice #, order #)

**4. Priority**
- Use sparingly (most items = Normal)
- High for urgent/time-sensitive items
- Low for background cleanup

---

## Best Practices: Processing

**1. Idempotency**
- Ensure processing can be retried safely
- If item is retried, same result should occur
- Avoid duplicate side effects

**2. Exception Classification**
- Business Exception: Data errors, validation failures
- Application Exception: Network errors, system issues
- Choose correctly to enable proper retry logic

**3. Error Logging**
- Log errors with context
- Include item Reference for traceability
- Store detailed errors in output data

**4. Progress Monitoring**
- Poll queue statistics periodically
- Alert on high failure rates
- Track processing speed

---

## Best Practices: Scalability

**1. Bulk Operations**
- Use BulkAddQueueItems for loading
- Add up to 100 items per call
- Much faster than individual adds

**2. Multiple Workers**
- Start multiple robots/scripts processing in parallel
- Each worker runs StartTransaction → Process → SetResult loop
- Orchestrator handles coordination automatically

**3. Queue Configuration**
- Set appropriate MaxRetryNumber (1-3 typical)
- Enable automatic retry for Application Exceptions
- Configure queue alerts for failures

**4. Clean Up**
- Archive old Successful/Failed items periodically
- Avoid queues with millions of items
- Use queue retention policies

## Common Pitfalls

**1. Not checking for null on StartTransaction**
```python
# ❌ Bad: Assumes item always returned
item = start_transaction(...)
data = json.loads(item['SpecificContent'])  # Fails if item is None

# ✅ Good: Check for None
item = start_transaction(...)
if item:
    data = json.loads(item['SpecificContent'])
```

**2. Wrong exception type**
- Using BusinessException for network errors → No retry
- Using ApplicationException for bad data → Infinite retries

**3. Not setting Reference**
- Hard to track specific items
- Difficult to troubleshoot
