## What Are Secrets?

**Secrets are sensitive data that grant access to resources:**

- 🔑 API keys and tokens
- 🔑 Passwords and passphrases
- 🔑 Database credentials
- 🔑 Private keys and certificates
- 🔑 OAuth tokens
- 🔑 Encryption keys

**If compromised, attackers gain unauthorized access**

---

## Types of Sensitive Data

**Always treat as secrets:**
- API keys (OpenAI, AWS, UiPath Orchestrator)
- Database connection strings with credentials
- Private SSH/TLS keys
- OAuth client secrets
- Encryption keys
- Service account credentials

**Configuration (not secrets):**
- Application names
- Port numbers
- Log levels
- Feature flags
- Public URLs

---

## The Cost of Exposed Secrets

**Real-world consequences:**

💸 **Financial**: Unauthorized API usage, AWS bills of $50,000+

🔓 **Data breach**: Customer data stolen

⚠️ **Reputation**: Public embarrassment, loss of trust

⚖️ **Legal**: GDPR fines, compliance violations

🚫 **Service disruption**: Attackers delete resources

**Proper secret handling isn't optional—it's critical**

## Secret Handling Principles

**1. Never hard-code secrets**
```python
# ❌ NEVER do this!
API_KEY = "sk-prod-abc123xyz"
```

**2. Never commit secrets to git**
```bash
# ✅ Always in .gitignore
echo ".env" >> .gitignore
```

**3. Use different secrets per environment**
```python
# Dev, staging, prod each have different keys
```

**4. Rotate secrets regularly**
```python
# Change every 90 days minimum
```

## Common Mistake #1: Hard-Coding Secrets

```python
# ❌ BAD: Hard-coded in source code
def connect_to_api():
    api_key = "sk-prod-abc123xyz789"
    return requests.get(
        "https://api.example.com/data",
        headers={"Authorization": f"Bearer {api_key}"}
    )
```

**Problems:**
- Secret visible to anyone with code access
- Can't change without code deployment
- Gets committed to git (exposed forever!)
- Same key for all environments

---

## Solution: Environment Variables

```python
# ✅ GOOD: Load from environment
import os

def connect_to_api():
    api_key = os.getenv("API_KEY")
    if not api_key:
        raise ValueError("API_KEY not set")

    return requests.get(
        "https://api.example.com/data",
        headers={"Authorization": f"Bearer {api_key}"}
    )
```

**Benefits:**
- Secret stays out of code
- Easy to change without redeployment
- Different values per environment
- Not in version control

---

## Common Mistake #2: Logging Secrets

```python
# ❌ BAD: Logs the secret
api_key = os.getenv("API_KEY")
logger.info(f"Connecting with API key: {api_key}")

# ❌ BAD: Error message contains password
try:
    db.connect(username, password)
except Exception as e:
    logger.error(f"Connection failed: {e}")
    # Exception might contain: "Auth failed for user 'admin' with password 'secret123'"
```

**Logs are:**
- Stored long-term
- Sent to monitoring systems
- Accessible to many people
- Sometimes made public in bug reports

---

## Solution: Sanitize Logs

```python
# ✅ GOOD: Mask the secret
api_key = os.getenv("API_KEY")
logger.info(f"Connecting with API key: {api_key[:4]}****")

# ✅ GOOD: Generic error message
try:
    db.connect(username, password)
except Exception as e:
    logger.error("Database connection failed")
    # Don't log the exception message that might contain credentials
```

**Only log what's safe for others to see**

---

## Common Mistake #3: Secrets in URLs

```python
# ❌ BAD: API key in URL query string
api_key = os.getenv("API_KEY")
url = f"http://api.example.com/data?key={api_key}"
response = requests.get(url)
```

**Problems:**
- URLs get logged (web server logs, proxy logs)
- URLs appear in browser history
- URLs sent over HTTP (unencrypted!)
- URLs can be shared/bookmarked

---

## Solution: Headers and HTTPS

```python
# ✅ GOOD: API key in header, HTTPS
api_key = os.getenv("API_KEY")
response = requests.get(
    "https://api.example.com/data",  # HTTPS not HTTP!
    headers={"Authorization": f"Bearer {api_key}"}
)
```

**Always:**
- Use HTTPS, never HTTP
- Send secrets in headers or request body
- Never in URL query parameters

---

## Common Mistake #4: Committing .env to Git

```bash
# ❌ BAD: .env committed to repo
git add .env
git commit -m "Add configuration"
git push

# Now your secrets are:
# - In git history forever
# - Accessible to anyone who clones
# - Public if repo is public
```

**Git never forgets—secrets stay in history even after deletion**

---

## Solution: .gitignore

```bash
# ✅ .gitignore
.env
.env.local
.env.*.local
*.env

# Commit .env.example instead
```

```bash
# .env.example (safe to commit)
API_KEY=your-api-key-here
DATABASE_URL=postgresql://user:pass@localhost:5432/db
```

**Team workflow:**
1. Clone repo
2. Copy .env.example to .env
3. Fill in real values
4. .env stays local

## What If You Already Committed Secrets?

**If you accidentally committed a secret:**

1. **Rotate/revoke the secret immediately**
   - Assume it's compromised
   - Create new credentials

2. **Remove from git history**
   ```bash
   # Use BFG Repo-Cleaner or git filter-branch
   bfg --replace-text secrets.txt repo.git
   ```

3. **Audit for unauthorized usage**
   - Check logs for suspicious activity

4. **Alert your team**
   - Document the incident

## Secret Rotation

**Why rotate secrets?**
- Limits exposure window if compromised
- Reduces risk from former employees
- Industry best practice
- Compliance requirement (PCI-DSS, SOC 2)

**When to rotate:**
- ✅ Every 90 days (minimum)
- ✅ Immediately if compromise suspected
- ✅ When employee leaves
- ✅ After security incident

---

## Rotation Strategy

**1. Generate new secret**
```python
new_api_key = generate_new_key()
```

**2. Deploy new secret (without removing old)**
```python
# Both old and new work temporarily
```

**3. Update all clients to use new secret**
```python
# Gradual rollout
```

**4. Verify all clients migrated**
```python
# Check usage logs
```

**5. Revoke old secret**
```python
# Safe to delete old key
```

**This avoids downtime during rotation**

## Automated Rotation

**Use secret management systems that support auto-rotation:**

- AWS Secrets Manager - Automatic rotation for RDS
- Azure Key Vault - Rotation policies
- HashiCorp Vault - Dynamic secrets

```python
import boto3

client = boto3.client('secretsmanager')

# Enable automatic rotation
client.rotate_secret(
    SecretId='prod/db/password',
    RotationRules={'AutomaticallyAfterDays': 90}
)
```

## Environment-Specific Secrets

**Each environment should have different secrets:**

```
Development:
  API_KEY=test-key-123
  DATABASE_URL=localhost

Staging:
  API_KEY=staging-key-456
  DATABASE_URL=staging-db.example.com

Production:
  API_KEY=prod-key-789
  DATABASE_URL=prod-db.example.com
```

**Why?**
- Compromised dev key doesn't affect production
- Limits blast radius
- Enables testing without risk

---

## Principle of Least Privilege

**Grant minimum permissions needed:**

```python
# ❌ BAD: Using admin credentials for read-only app
DATABASE_URL=postgresql://admin:adminpass@db/myapp

# ✅ GOOD: Using read-only credentials
DATABASE_URL=postgresql://readonly:pass@db/myapp
```

**If credentials are compromised:**
- Admin: Attacker can delete all data
- Read-only: Attacker can only read data

**Always use the minimum privilege required**

## Using AWS Secrets Manager

```python
import boto3
import json

def get_secret(secret_name):
    client = boto3.client('secretsmanager', region_name='us-east-1')

    try:
        response = client.get_secret_value(SecretId=secret_name)
        return json.loads(response['SecretString'])
    except Exception as e:
        logger.error(f"Failed to retrieve secret: {e}")
        raise

# Usage
secrets = get_secret('prod/database')
db_url = f"postgresql://{secrets['username']}:{secrets['password']}@{secrets['host']}/db"
```

**Benefits: Encrypted, audited, rotatable, access-controlled**

## Never Use Defaults for Secrets

```python
# ❌ BAD: Default secret value
api_key = os.getenv("API_KEY", "default-key-123")

# Problems:
# - If env var not set, uses insecure default
# - Silent failure—no indication something's wrong
# - May work in dev but fail mysteriously in prod
```

```python
# ✅ GOOD: Fail fast if missing
api_key = os.getenv("API_KEY")
if not api_key:
    raise ValueError("API_KEY environment variable is required")
```

**Fail immediately with a clear error**

## Validate Required Secrets at Startup

```python
import os
import sys

REQUIRED_SECRETS = [
    "API_KEY",
    "DATABASE_URL",
    "ORCHESTRATOR_API_KEY",
    "ENCRYPTION_KEY"
]

def validate_secrets():
    missing = [s for s in REQUIRED_SECRETS if not os.getenv(s)]

    if missing:
        print(f"ERROR: Missing required secrets: {', '.join(missing)}")
        print("Please set these environment variables")
        sys.exit(1)

# Call at application startup
validate_secrets()
```

**Prevents mysterious failures later**

## Secure Transmission

```python
# ❌ BAD: HTTP (unencrypted)
response = requests.post(
    "http://api.example.com/login",
    json={"password": password}
)

# ✅ GOOD: HTTPS (encrypted)
response = requests.post(
    "https://api.example.com/login",
    json={"password": password}
)
```

**Always:**
- Use TLS/HTTPS for transmission
- Verify certificates (don't disable SSL verification)
- Use modern TLS versions (1.2+)

## Secure Storage

**Never store secrets in:**
- ❌ Plain text files
- ❌ Source code
- ❌ Database (unencrypted)
- ❌ Configuration files in repo
- ❌ Wiki or documentation

**Do store secrets in:**
- ✅ Secret management systems (encrypted)
- ✅ Platform environment variables
- ✅ Encrypted key stores
- ✅ Hardware security modules (HSM) for critical secrets

## Access Control

**Who should access secrets?**

**Development:**
- Developers: Dev/staging secrets only
- No access to production secrets

**Production:**
- Operations team: Limited access
- Automated systems: Service accounts with minimal permissions
- Audit all access

**Use tools like AWS IAM, Azure RBAC to enforce**

## Incident Response

**If a secret is compromised:**

1. **Rotate immediately** - Don't wait
2. **Revoke old secret** - Cut off attacker access
3. **Audit usage** - Check for unauthorized activity
4. **Assess damage** - What did they access?
5. **Update procedures** - Prevent recurrence
6. **Document** - Create incident report
7. **Notify** - Alert affected parties if needed

**Speed is critical—every minute counts**

## Real-World Example: Secure Agent Config

```python
import os
import sys
import logging
from typing import Optional

class SecureConfig:
    """Secure configuration for UiPath agent."""

    REQUIRED_SECRETS = [
        "ORCHESTRATOR_API_KEY",
        "DATABASE_PASSWORD"
    ]

    def __init__(self):
        self._validate_secrets()
        self._load_secrets()

    def _validate_secrets(self):
        missing = [s for s in self.REQUIRED_SECRETS if not os.getenv(s)]
        if missing:
            logging.error(f"Missing secrets: {', '.join(missing)}")
            sys.exit(1)

    def _load_secrets(self):
        self.orchestrator_key = os.getenv("ORCHESTRATOR_API_KEY")
        self.db_password = os.getenv("DATABASE_PASSWORD")

        # Log that secrets were loaded (not the values!)
        logging.info("All required secrets loaded successfully")
```
