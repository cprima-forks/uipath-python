## What is a Process?

**A Process is a published automation package ready for execution**

```
UiPath Studio → Publish → Package (.nupkg)
                            ↓
                    Orchestrator Deployment
                            ↓
                    Process (Release)
```

**Characteristics:**
- Contains the automation workflow
- Has a version number (1.0.0, 1.0.1, etc.)
- Deployed to specific folder(s)
- Can be assigned to robots
- Identified by ReleaseKey

---

## Process Components

**A Process includes:**

- **Workflow XAML:** The actual automation logic
- **Dependencies:** Libraries and packages
- **Configuration:** Settings and constants
- **Entry Point:** Which workflow to start
- **Metadata:** Name, version, description

**Think of it as:** The "program" or "application" that robots execute

---

## Process in Orchestrator

**Viewing Processes:**

```
Tenant → Folder → Processes
```

**Each Process shows:**
- Name (e.g., "Invoice Processing")
- Version (e.g., "1.0.5")
- Package Name
- Entry Point
- Associated robots

**API Endpoint:** `/odata/Releases`
(Processes are called "Releases" in the API)

---

## What is a Job?

**A Job is a single execution of a Process by a robot**

```
Process: "Invoice Processing"
    ↓ Start execution
Job #1: Running on Robot-01
Job #2: Running on Robot-02
Job #3: Completed on Robot-01
```

**Key Points:**
- One Process → Many Jobs
- Each job is independent
- Tracks execution from start to finish
- Records results and logs

**Think of it as:** A "run" or "instance" of the program

---

## Job Characteristics

**Each Job tracks:**

- **Which Process** was executed (ReleaseKey)
- **Which Robot** executed it
- **When** it started and ended
- **Current State** (Pending, Running, Successful, etc.)
- **Input Arguments** (if any)
- **Output Arguments** (if any)
- **Logs and Screenshots**
- **Error Information** (if failed)

---

## Process vs Job

| Aspect | Process | Job |
|--------|---------|-----|
| **What** | Automation definition | Execution instance |
| **Count** | One per version | Many per process |
| **Lifespan** | Until deleted/updated | Until completion |
| **API Name** | Release | Job |
| **Endpoint** | /odata/Releases | /odata/Jobs |
| **Analogy** | Program/App | Running instance |

**Example:** "Invoice Processing" process has been run 1,000 times → 1 process, 1,000 jobs

---

## Job Lifecycle

```
1. Created (Pending)
        ↓
2. Assigned to Robot
        ↓
3. Robot starts execution (Running)
        ↓
4. Completion:
   • Successful ✓
   • Faulted (Error) ✗
   • Stopped (Manual) ⏸
```

**Each stage is tracked** with timestamps and state changes

---

## Job States

| State | Meaning | Next Steps |
|-------|---------|------------|
| **Pending** | Waiting for available robot | Wait or check robot availability |
| **Running** | Currently executing | Monitor for completion |
| **Successful** | Completed without errors | Retrieve output arguments |
| **Faulted** | Failed with error | Check logs and error details |
| **Stopped** | Manually stopped by user | Investigate why stopped |

## Starting Jobs: Overview

**To start a job, you need:**

1. **Process to execute** (ReleaseKey)
2. **Folder context** (X-UIPATH-OrganizationUnitId)
3. **Robot selection strategy**
4. **Optional:** Input arguments, priority

**API Method:**
```
POST /odata/Jobs/UiPath.Server.Configuration.OData.StartJobs
```

---

## StartJobs API Endpoint

**Full endpoint:**
```
POST {base_url}/odata/Jobs/UiPath.Server.Configuration.OData.StartJobs
```

**This is an OData Action** (special operation with specific input structure)

**Headers required:**
- Authorization: Bearer {token}
- X-UIPATH-OrganizationUnitId: {folder_id}
- Content-Type: application/json

**Body:** JSON payload with job configuration

---

## StartJobs Payload Structure

```json
{
  "startInfo": {
    "ReleaseKey": "a1b2c3d4-1234-5678-90ab-cdef12345678",
    "Strategy": "JobsCount",
    "RobotIds": [],
    "NoOfRobots": 0,
    "JobsCount": 0,
    "Source": "Manual",
    "InputArguments": "{\"InvoiceID\": \"INV-001\"}"
  }
}
```

**Key fields:** ReleaseKey (which process), Strategy (how to select robots)

---

## Getting the ReleaseKey

**ReleaseKey identifies the Process to execute**

```python
# Get all releases (processes) in a folder
response = requests.get(
    f'{base_url}/odata/Releases',
    headers={
        'Authorization': f'Bearer {token}',
        'X-UIPATH-OrganizationUnitId': folder_id
    }
)

releases = response.json()['value']

# Find your process
invoice_process = next(
    r for r in releases
    if r['ProcessKey'] == 'InvoiceProcessing'
)

release_key = invoice_process['Key']  # This is the ReleaseKey
```

## Robot Selection Strategies

**Three strategies for choosing which robot(s) execute the job:**

**1. Specific**
- You specify exact robot IDs
- Use when you need specific robots
- Example: dedicated robot for sensitive processing

**2. JobsCount**
- Orchestrator selects robot(s) with fewest running jobs
- Load balancing
- Most common for production

**3. Random**
- Random selection from available robots
- Rarely used

---

## Strategy Example: Specific

```python
{
  "startInfo": {
    "ReleaseKey": "abc123...",
    "Strategy": "Specific",
    "RobotIds": [101, 102],  # Specific robot IDs
    "NoOfRobots": 0,
    "InputArguments": "{}"
  }
}
```

**Use case:** Run on dedicated high-priority robots

---

## Strategy Example: JobsCount

```python
{
  "startInfo": {
    "ReleaseKey": "abc123...",
    "Strategy": "JobsCount",
    "RobotIds": [],  # Empty - let Orchestrator choose
    "NoOfRobots": 2,  # Start 2 parallel jobs
    "JobsCount": 0,
    "InputArguments": "{}"
  }
}
```

**Use case:** Load-balanced execution across available robots

## Complete StartJobs Example

```python
import requests
import json

def start_job(base_url, token, folder_id, release_key, input_args=None):
    """Start a job with optional input arguments"""

    payload = {
        "startInfo": {
            "ReleaseKey": release_key,
            "Strategy": "JobsCount",
            "RobotIds": [],
            "NoOfRobots": 0,
            "InputArguments": json.dumps(input_args or {})
        }
    }

    response = requests.post(
        f'{base_url}/odata/Jobs/UiPath.Server.Configuration.OData.StartJobs',
        json=payload,
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id),
            'Content-Type': 'application/json'
        }
    )

    response.raise_for_status()
    return response.json()['value']  # Returns list of created jobs
```

## Passing Input Arguments

**Input arguments are parameters your workflow receives**

**In the workflow:**
```
in_InvoiceID (String)
in_Amount (Int32)
in_Priority (String)
```

**In the API call:**
```python
input_args = {
    "in_InvoiceID": "INV-12345",
    "in_Amount": 1500,
    "in_Priority": "High"
}

jobs = start_job(base_url, token, folder_id, release_key, input_args)
```

**Important:** Argument names must match workflow exactly (including "in_" prefix if used)

---

## Input Arguments Format

**InputArguments is a JSON string:**

```python
# ✅ Correct: JSON object as string
"InputArguments": "{\"InvoiceID\": \"INV-001\", \"Amount\": 1500}"

# ❌ Wrong: Python dict
"InputArguments": {"InvoiceID": "INV-001"}

# ✅ Correct way in Python:
import json
input_args = {"InvoiceID": "INV-001", "Amount": 1500}
"InputArguments": json.dumps(input_args)
```

**Remember:** Serialize to JSON string with `json.dumps()`

## Monitoring Job Execution

**After starting a job, you need to monitor its progress**

**Approach:**
1. Start job → Get job ID
2. Poll job status periodically
3. Check State field
4. Wait for completion (Successful, Faulted, or Stopped)

```python
def wait_for_job(base_url, token, folder_id, job_id, poll_interval=5):
    """Poll job until completion"""
    while True:
        job = get_job(base_url, token, folder_id, job_id)
        state = job['State']

        if state in ['Successful', 'Faulted', 'Stopped']:
            return job  # Completed

        print(f"Job {job_id}: {state}")
        time.sleep(poll_interval)
```

## Job State Transitions

```
Pending → Running → Successful
                 ↘ Faulted
                 ↘ Stopped
```

**Typical timeline:**
- **Pending:** Seconds (if robots available)
- **Running:** Minutes to hours (depends on workflow)
- **Final State:** Permanent

**If Pending for long time:** Check robot availability

## Job Priority

**Priority controls execution order when robots are busy**

```python
payload = {
    "startInfo": {
        "ReleaseKey": release_key,
        "Strategy": "JobsCount",
        "Source": "Manual",
        "InputArguments": "{}",
        "Priority": "High"  # High, Normal, Low
    }
}
```

**Effect:** High-priority jobs execute before Normal, which execute before Low

**Use case:** Urgent processing gets priority over batch jobs

## Retrieving Output Arguments

**Output arguments are results returned by the workflow**

**In the workflow:**

**After job completes:**

```python
job = get_job(base_url, token, folder_id, job_id)
```

## Complete Job Execution Example

```python
def execute_process(base_url, token, folder_id, release_key, inputs):
    """Start job, wait for completion, return outputs"""

    # 1. Start job
    print("Starting job...")
    jobs = start_job(base_url, token, folder_id, release_key, inputs)
    job_id = jobs[0]['Id']
    print(f"Job ID: {job_id}")

    # 2. Monitor until completion
    print("Monitoring job...")
    final_job = wait_for_job(base_url, token, folder_id, job_id)

    # 3. Check result
    if final_job['State'] == 'Successful':
        outputs = json.loads(final_job['OutputArguments'])
        print("Job completed successfully!")
        return outputs
    else:
        error_info = final_job['Info']
        raise Exception(f"Job failed: {error_info}")

# Usage
result = execute_process(
    base_url, token, folder_id, release_key,
    inputs={"InvoiceID": "INV-001"}
)
print(f"Result: {result}")
```

## Handling Job Errors

**When job State is 'Faulted':**

```python
job = get_job(base_url, token, folder_id, job_id)

if job['State'] == 'Faulted':
    print(f"Error: {job['Info']}")  # Error summary

    # Get detailed logs
    logs_response = requests.get(
        f'{base_url}/odata/RobotLogs',
        params={
            '$filter': f"JobKey eq {job['Key']}",
            '$orderby': 'TimeStamp desc'
        },
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id)
        }
    )

    logs = logs_response.json()['value']
    for log in logs:
        if log['Level'] == 'Error':
            print(f"  {log['TimeStamp']}: {log['Message']}")
```

## Job Troubleshooting

**Common issues:**

**Job stuck in Pending:**
- No available robots
- Robots don't have access to folder
- No robot has required environment
- All robots disconnected

**Job Faulted immediately:**
- Invalid input arguments
- Missing dependencies in robot environment
- Permission errors

**Job running forever:**
- Workflow has infinite loop
- Waiting for external resource
- Check robot logs for clues

## Job Scheduling

**Two ways to run jobs:**

**1. Immediate Execution** (what we've covered)
```python
POST /odata/Jobs/.../StartJobs
```
Runs once, right now

**2. Scheduled Execution**
```python
POST /odata/ProcessSchedules
```
Runs automatically based on schedule (daily, hourly, cron, etc.)

---

## Creating a Schedule

```python
def create_schedule(base_url, token, folder_id, release_key):
    """Create daily schedule at 9 AM"""

    schedule_payload = {
        "Name": "Daily Invoice Processing",
        "ReleaseKey": release_key,
        "Enabled": True,
        "TimeZoneId": "UTC",
        "StartProcessCron": "0 9 * * *",  # Daily at 9 AM
        "StartProcessCronDetails": {
            "Type": "Advanced",  # or "Basic"
            "AdvancedCronExpression": "0 9 * * *"
        },
        "InputArguments": "{\"Mode\": \"Daily\"}"
    }

    response = requests.post(
        f'{base_url}/odata/ProcessSchedules',
        json=schedule_payload,
        headers={
            'Authorization': f'Bearer {token}',
            'X-UIPATH-OrganizationUnitId': str(folder_id),
            'Content-Type': 'application/json'
        }
    )

    return response.json()
```

---

## Cron Expressions

**Schedule patterns:**

```
"0 9 * * *"      # Daily at 9:00 AM
"0 */4 * * *"    # Every 4 hours
"30 8 * * 1-5"   # Weekdays at 8:30 AM
"0 0 1 * *"      # First day of month
"0 12 * * 6"     # Saturdays at noon
```

**Format:** `minute hour day month day-of-week`

**Tool:** Use crontab.guru for help creating expressions

## OData Filters for Jobs

**Common filters:**

```python

robots = get_available_robots(base_url, token, folder_id)
```

```python
required = ['InvoiceID', 'Amount']
```

## Best Practices: Error Handling

**1. Always check job state**
```python
if job['State'] != 'Successful':
    # Handle error
```

**2. Retrieve logs for failed jobs**

**3. Implement retry logic**
```python
def start_job_with_retry(max_retries=3):
    for attempt in range(max_retries):
        try:
            return start_job(...)
        except Exception as e:
            if attempt == max_retries - 1:
                raise
            time.sleep(2 ** attempt)  # Exponential backoff
```

**4. Handle rate limits** (429 errors)

---

## Best Practices: Performance

**1. Don't poll too frequently**
```python
# ✅ Good: 5-10 second intervals
time.sleep(5)

# ❌ Bad: Polling every second
time.sleep(1)  # Too aggressive
```

**2. Use OData filtering to reduce data**
```python
# Get only necessary fields
params = {'$select': 'Id,State,Info'}
```

**3. Cache release keys**
```python
# Look up once, reuse
release_keys = get_all_release_keys()  # Cache
release_key = release_keys['InvoiceProcessing']
```

**4. Batch operations when possible**

## Best Practices: Monitoring

**1. Log job IDs for tracking**
```python
logger.info(f"Started job {job_id} for invoice {invoice_id}")
```

**2. Track execution time**
```python
start = time.time()
job = wait_for_job(...)
duration = time.time() - start
logger.info(f"Job completed in {duration:.1f} seconds")
```

**3. Alert on long-running jobs**

**4. Monitor job queue depth**
```python
pending_jobs = get_jobs(..., filters="State eq 'Pending'")
if len(pending_jobs) > 100:
    alert("Job queue backlog!")
```

## Common Patterns

**Pattern 1: Batch Processing**
```python
for invoice in invoices:
    start_job(release_key, inputs={"InvoiceID": invoice.id})
    time.sleep(0.5)  # Rate limiting
```

**Pattern 2: Parallel Processing**
```python
job_ids = []
for invoice in invoices:
    jobs = start_job(release_key, inputs={"InvoiceID": invoice.id})
    job_ids.append(jobs[0]['Id'])

# Wait for all
results = [wait_for_job(..., job_id) for job_id in job_ids]
```

**Pattern 3: Pipeline**
```python
# Job 1: Extract
job1 = execute_process(release_key_extract, {})

# Job 2: Transform (using output from Job 1)
job2 = execute_process(release_key_transform, job1_outputs)
```
