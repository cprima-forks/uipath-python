## Running Multiple Coroutines: asyncio.gather()

```python
import asyncio

async def fetch_user(user_id):
    await asyncio.sleep(1)
    return f"User {user_id}"

async def fetch_orders(user_id):
    await asyncio.sleep(1)
    return f"Orders for {user_id}"

async def fetch_profile(user_id):
    await asyncio.sleep(1)
    return f"Profile for {user_id}"

async def main():
    # Run all concurrently
    user, orders, profile = await asyncio.gather(
        fetch_user(123),
        fetch_orders(123),
        fetch_profile(123)
    )
    print(user, orders, profile)

asyncio.run(main())
# Time: ~1 second (not 3!)
```

---

## asyncio.gather() Key Features

**Returns results in order:**
```python
results = await asyncio.gather(
    task_a(),  # Result will be results[0]
    task_b(),  # Result will be results[1]
    task_c()   # Result will be results[2]
)
```

**Not in completion order—in the order you passed them**

**Waits for all tasks:**
- All tasks must complete before gather() returns
- If one fails, gather() raises immediately (by default)
- Other tasks continue running in background

---

## asyncio.gather() with Unpacking

```python
# Fetch data from multiple APIs
apis = [
    "https://api1.example.com/data",
    "https://api2.example.com/data",
    "https://api3.example.com/data"
]

async def main():
    # Create list of coroutines
    tasks = [fetch_url(url) for url in apis]

    # Unpack list with *
    results = await asyncio.gather(*tasks)

    print(f"Fetched {len(results)} results")
```

**Use `*tasks` to unpack a list of coroutines**

## Handling Exceptions in gather()

```python
async def risky_task(n):
    if n == 2:
        raise ValueError("Task 2 failed!")
    return f"Result {n}"

# ❌ Default: First exception raises immediately
try:
    results = await asyncio.gather(
        risky_task(1),
        risky_task(2),
        risky_task(3)
    )
except ValueError as e:
    print(f"Error: {e}")
    # Other tasks continue in background but results are lost!
```

**Problem**: Exception stops gather(), but other tasks keep running

---

## gather() with return_exceptions=True

```python
# ✅ Better: Collect exceptions as results
results = await asyncio.gather(
    risky_task(1),
    risky_task(2),
    risky_task(3),
    return_exceptions=True
)

# Check each result
for i, result in enumerate(results):
    if isinstance(result, Exception):
        print(f"Task {i} failed: {result}")
    else:
        print(f"Task {i} succeeded: {result}")
```

**With return_exceptions=True:**
- Exceptions become results, not raised
- All tasks complete
- You can handle each failure individually

## Creating Tasks: asyncio.create_task()

```python
async def main():
    # Create tasks (they start immediately!)
    task1 = asyncio.create_task(fetch_data("api1"))
    task2 = asyncio.create_task(fetch_data("api2"))

    # Tasks are now running in background
    print("Tasks started")

    # Do other work here...
    await asyncio.sleep(0.5)

    # Collect results when needed
    result1 = await task1
    result2 = await task2
```

**Key difference from gather():**
- create_task() starts execution immediately
- Returns a Task object you can await later
- Gives you control over when to collect results

---

## When to Use gather() vs create_task()

**Use asyncio.gather() when:**
- ✅ You want to start all tasks and wait for all results
- ✅ You have a list of similar operations
- ✅ You want results in order

**Use asyncio.create_task() when:**
- ✅ You want to start tasks early, collect results later
- ✅ You need task objects for cancellation or status checks
- ✅ You want more control over task lifecycle

```python
# gather() pattern
results = await asyncio.gather(task1(), task2(), task3())

# create_task() pattern
t1 = asyncio.create_task(task1())
t2 = asyncio.create_task(task2())
results = [await t1, await t2]
```

## Task Management

**Task objects provide:**
- `task.cancel()` - Request cancellation
- `task.cancelled()` - Check if cancelled
- `task.done()` - Check if completed
- `task.result()` - Get result (or raise exception)
- `task.exception()` - Get exception if failed
- `task.add_done_callback(fn)` - Run function when done

```python
task = asyncio.create_task(long_operation())

# Check status
if task.done():
    print("Task finished")

# Get result
result = task.result()  # Raises if task raised
```

## Cancelling Tasks

```python
async def slow_operation():
    try:
        await asyncio.sleep(10)
        return "Done"
    except asyncio.CancelledError:
        print("Task was cancelled, cleaning up...")
        # Perform cleanup here
        raise  # Re-raise to complete cancellation

async def main():
    task = asyncio.create_task(slow_operation())

    await asyncio.sleep(1)  # Let it run briefly

    task.cancel()  # Request cancellation

    try:
        await task
    except asyncio.CancelledError:
        print("Task cancelled successfully")
```

**Cancellation is cooperative—task must await to be cancelled**

## Timeouts with asyncio.wait_for()

```python
async def slow_api_call():
    await asyncio.sleep(10)
    return "Data"

async def main():
    try:
        # Wait maximum 5 seconds
        result = await asyncio.wait_for(
            slow_api_call(),
            timeout=5.0
        )
        print(result)
    except asyncio.TimeoutError:
        print("Operation timed out!")
```

**asyncio.wait_for() automatically cancels the task on timeout**

Perfect for API calls with time limits

---

## Timeout Context Manager (Python 3.11+)

```python
async def main():
    try:
        async with asyncio.timeout(5.0):
            result = await slow_operation()
            print(result)
    except asyncio.TimeoutError:
        print("Timed out!")
```

**Cleaner syntax for timeouts**

Any await inside the context is subject to the timeout

Works with multiple operations:
```python
async with asyncio.timeout(10.0):
    await operation1()
    await operation2()
    await operation3()
```

## asyncio.wait() - Lower-Level Control

```python
async def main():
    tasks = {
        asyncio.create_task(task1()),
        asyncio.create_task(task2()),
        asyncio.create_task(task3())
    }

    # Wait for all tasks
    done, pending = await asyncio.wait(tasks)

    # Process completed tasks
    for task in done:
        result = task.result()
        print(f"Result: {result}")
```

**asyncio.wait() returns two sets:**
- `done` - Completed tasks
- `pending` - Still running tasks

More control than gather(), but more complex

---

## wait() with Conditions

```python
# Return when first task completes
done, pending = await asyncio.wait(
    tasks,
    return_when=asyncio.FIRST_COMPLETED
)

# Return when first task fails
done, pending = await asyncio.wait(
    tasks,
    return_when=asyncio.FIRST_EXCEPTION
)

# Return when all tasks complete (default)
done, pending = await asyncio.wait(
    tasks,
    return_when=asyncio.ALL_COMPLETED
)

# Don't forget to cancel pending tasks!
for task in pending:
    task.cancel()
```

## asyncio.as_completed() - Process as Done

```python
async def main():
    tasks = [
        fetch_data("api1"),
        fetch_data("api2"),
        fetch_data("api3")
    ]

    # Process results as they complete
    for coro in asyncio.as_completed(tasks):
        result = await coro
        print(f"Got result: {result}")
```

**as_completed() yields coroutines in completion order**

Useful when you want to process results immediately

Not in input order—whichever finishes first

## asyncio.Queue - Producer/Consumer Pattern

```python
async def producer(queue):
    for i in range(5):
        await asyncio.sleep(0.5)
        await queue.put(f"Item {i}")
    await queue.put(None)  # Signal completion

async def consumer(queue):
    while True:
        item = await queue.get()
        if item is None:
            break
        print(f"Processing {item}")
        queue.task_done()

async def main():
    queue = asyncio.Queue()

    await asyncio.gather(
        producer(queue),
        consumer(queue)
    )
```

---

## asyncio.Queue Key Methods

```python
queue = asyncio.Queue(maxsize=10)

# Producer operations
await queue.put(item)        # Add item (waits if full)
queue.put_nowait(item)       # Add item (raises if full)

# Consumer operations
item = await queue.get()     # Remove item (waits if empty)
item = queue.get_nowait()    # Remove item (raises if empty)
queue.task_done()            # Mark item as processed

# Status checks
queue.qsize()                # Current size
queue.empty()                # Is queue empty?
queue.full()                 # Is queue full?

# Wait for all items processed
await queue.join()
```

## Real-World Example: Web Scraper with Queue

```python
async def fetch_page(session, url):
    async with session.get(url) as response:
        return await response.text()

async def worker(queue, session):
    while True:
        url = await queue.get()
        if url is None:
            break

        try:
            html = await fetch_page(session, url)
            print(f"Fetched {url}: {len(html)} bytes")
        finally:
            queue.task_done()

async def main():
    urls = ["url1", "url2", "url3", ...]
    queue = asyncio.Queue()

    # Add URLs to queue
    for url in urls:
        await queue.put(url)

    # Create worker tasks
    workers = [
        asyncio.create_task(worker(queue, session))
        for _ in range(5)  # 5 concurrent workers
    ]

    await queue.join()  # Wait for all URLs processed

    # Stop workers
    for _ in workers:
        await queue.put(None)
```

## Limiting Concurrency: asyncio.Semaphore

```python
# Limit to 5 concurrent operations
semaphore = asyncio.Semaphore(5)

async def fetch_with_limit(url):
    async with semaphore:
        # Only 5 tasks can be here at once
        return await fetch_url(url)

async def main():
    urls = [f"https://api.example.com/page/{i}" for i in range(100)]

    # Creates 100 tasks, but only 5 run concurrently
    results = await asyncio.gather(
        *[fetch_with_limit(url) for url in urls]
    )
```

**Perfect for rate-limiting API calls**

---

## Semaphore vs Queue

**Use Semaphore when:**
- ✅ You want to limit concurrent operations
- ✅ All items are known upfront
- ✅ No producer/consumer coordination needed

**Use Queue when:**
- ✅ Items arrive over time (streaming)
- ✅ Producer and consumer run at different rates
- ✅ You need work coordination
- ✅ Multiple producers or consumers

```python
# Semaphore: Limit concurrent API calls
async with semaphore:
    await api_call()

# Queue: Process items as they arrive
item = await queue.get()
```

## asyncio.Lock - Mutual Exclusion

```python
lock = asyncio.Lock()
counter = 0

async def increment():
    global counter
    async with lock:
        # Only one task can be here at a time
        current = counter
        await asyncio.sleep(0.01)  # Simulate work
        counter = current + 1

async def main():
    await asyncio.gather(*[increment() for _ in range(100)])
    print(f"Counter: {counter}")  # 100 (correct!)
```

**Without lock, you'd get race conditions**

Critical for shared state in async code

---

## When to Use Lock vs Semaphore

**Use Lock when:**
- ✅ You need exclusive access to a resource
- ✅ Only one task should proceed at a time
- ✅ Protecting shared state

**Use Semaphore when:**
- ✅ You want to limit concurrency to N tasks
- ✅ Rate limiting (e.g., max 5 API calls)
- ✅ Resource pool management

```python
# Lock: Only 1 task
lock = asyncio.Lock()
async with lock:
    pass  # Only 1 task here

# Semaphore: Up to N tasks
sem = asyncio.Semaphore(5)
async with sem:
    pass  # Up to 5 tasks here
```

## asyncio.Event - Signaling Between Tasks

```python
event = asyncio.Event()

async def waiter():
    print("Waiting for event...")
    await event.wait()  # Block until event is set
    print("Event received!")

async def setter():
    await asyncio.sleep(2)
    print("Setting event")
    event.set()  # Wake up all waiters

async def main():
    await asyncio.gather(waiter(), setter())
```

**Use Event for task synchronization and signaling**

## Done Callbacks

```python
def task_done(task):
    try:
        result = task.result()
        print(f"Task completed: {result}")
    except Exception as e:
        print(f"Task failed: {e}")

async def main():
    task = asyncio.create_task(some_operation())

    # Register callback
    task.add_done_callback(task_done)

    # Callback runs when task completes
    # (We don't need to await)
```

**Callbacks run when task finishes (success or failure)**

Useful for logging, cleanup, or triggering other operations

## Real-World Example: Concurrent Document Processor

```python
import aiofiles
import asyncio

async def process_document(doc_path, semaphore):
    async with semaphore:
        print(f"Processing {doc_path}")

        async with aiofiles.open(doc_path) as f:
            content = await f.read()

        # Simulate processing
        await asyncio.sleep(1)

        return {
            "path": doc_path,
            "length": len(content),
            "status": "processed"
        }

async def process_batch(doc_paths, max_concurrent=5):
    semaphore = asyncio.Semaphore(max_concurrent)

    tasks = [
        process_document(path, semaphore)
        for path in doc_paths
    ]

    results = await asyncio.gather(*tasks, return_exceptions=True)

    # Separate successes and failures
    successes = [r for r in results if not isinstance(r, Exception)]
    failures = [r for r in results if isinstance(r, Exception)]

    print(f"Processed: {len(successes)}, Failed: {len(failures)}")
    return successes
```

## Real-World Example: API Client with Retry

```python
import aiohttp

async def api_call_with_retry(url, max_retries=3):
    for attempt in range(max_retries):
        try:
            async with asyncio.timeout(5.0):
                async with aiohttp.ClientSession() as session:
                    async with session.get(url) as response:
                        return await response.json()
        except (asyncio.TimeoutError, aiohttp.ClientError) as e:
            if attempt == max_retries - 1:
                raise
            print(f"Attempt {attempt + 1} failed, retrying...")
            await asyncio.sleep(2 ** attempt)  # Exponential backoff

async def fetch_all_agents(agent_ids):
    tasks = [
        api_call_with_retry(f"https://api.example.com/agents/{id}")
        for id in agent_ids
    ]

    results = await asyncio.gather(*tasks, return_exceptions=True)

    return [r for r in results if not isinstance(r, Exception)]
```

## Real-World Example: Rate-Limited Scraper

```python
class RateLimitedScraper:
    def __init__(self, rate_limit=10):
        self.semaphore = asyncio.Semaphore(rate_limit)
        self.session = None

    async def __aenter__(self):
        self.session = aiohttp.ClientSession()
        return self

    async def __aexit__(self, *args):
        await self.session.close()

    async def fetch(self, url):
        async with self.semaphore:
            async with self.session.get(url) as response:
                return await response.text()

# Usage
async def main():
    urls = [f"https://example.com/page/{i}" for i in range(100)]

    async with RateLimitedScraper(rate_limit=10) as scraper:
        results = await asyncio.gather(
            *[scraper.fetch(url) for url in urls]
        )

    print(f"Fetched {len(results)} pages")
```

## Performance Tips

**DO:**
- ✅ Use gather() for simple concurrent execution
- ✅ Use Semaphore to limit API rate
- ✅ Set timeouts on all network operations
- ✅ Handle exceptions with return_exceptions=True
- ✅ Use Queue for producer-consumer patterns
- ✅ Cancel pending tasks when done

**DON'T:**
- ❌ Create unlimited concurrent tasks
- ❌ Forget to handle exceptions in gather()
- ❌ Block the event loop in critical sections
- ❌ Leave tasks running after they're no longer needed

## Best Practices

**1. Always set timeouts:**
```python
async with asyncio.timeout(5.0):
    await operation()
```

**2. Handle exceptions in gather:**
```python
results = await asyncio.gather(*tasks, return_exceptions=True)
```

**3. Limit concurrency:**
```python
async with semaphore:
    await api_call()
```

**4. Clean up tasks:**
```python
for task in pending:
```

## Common Pitfalls

**Pitfall 1: Not limiting concurrency**
```python
# ❌ BAD: Creates 10,000 concurrent connections!
tasks = [fetch_url(url) for url in urls]
results = await asyncio.gather(*tasks)

# ✅ GOOD: Limit to 10 concurrent
semaphore = asyncio.Semaphore(10)
async def fetch_limited(url):
    async with semaphore:
        return await fetch_url(url)
```

**Pitfall 2: Ignoring exceptions**
```python
# ❌ BAD: One failure stops everything
results = await asyncio.gather(*tasks)

# ✅ GOOD: Handle failures gracefully
results = await asyncio.gather(*tasks, return_exceptions=True)
```

---

## Common Pitfalls (continued)

**Pitfall 3: Not canceling tasks**
```python
# ❌ BAD: Tasks keep running forever
done, pending = await asyncio.wait(tasks, timeout=5.0)
# Pending tasks still running!

# ✅ GOOD: Cancel what you don't need
for task in pending:
    task.cancel()
```

**Pitfall 4: Race conditions with shared state**
```python
# ❌ BAD: Multiple tasks modifying counter
counter += 1

# ✅ GOOD: Protect with lock
async with lock:
    counter += 1
```

✅ **asyncio.gather()** runs coroutines concurrently, returns results in order

✅ **asyncio.create_task()** starts tasks immediately, gives control

✅ **asyncio.wait_for()** enforces timeouts, cancels on expiry

✅ **asyncio.Queue** coordinates producer-consumer patterns

✅ **asyncio.Semaphore** limits concurrent operations

✅ **asyncio.Lock** ensures mutual exclusion

✅ **Always handle exceptions** with return_exceptions=True

✅ **Always limit concurrency** to avoid overwhelming systems
