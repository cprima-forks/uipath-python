## Semantic Versioning (SemVer)

The UiPath SDK follows **Semantic Versioning 2.0.0**

**Format:** `MAJOR.MINOR.PATCH`

**Example:** `0.2.1`
- **MAJOR:** 0 (breaking changes)
- **MINOR:** 2 (new features, backward-compatible)
- **PATCH:** 1 (bug fixes, backward-compatible)

---

## SemVer Rules

### MAJOR Version (X.0.0)

**Increments when:**
- Breaking changes introduced
- API changes incompatible with previous versions
- Requires code updates

**Example:** `0.9.5 → 1.0.0`

---

## SemVer Rules (Continued)

### MINOR Version (0.X.0)

**Increments when:**
- New features added
- Backward-compatible changes
- No breaking changes
- Existing code continues to work

**Example:** `0.2.5 → 0.3.0`

---

## SemVer Rules (Continued)

### PATCH Version (0.0.X)

**Increments when:**
- Bug fixes only
- No new features
- No breaking changes
- Backward-compatible

**Example:** `0.2.1 → 0.2.2`

---

## Special Case: Version 0.x.y

**Important:** Versions below 1.0.0 are considered **unstable**

**Rules for 0.x.y:**
- MINOR changes (0.2.0 → 0.3.0) may include breaking changes
- PATCH changes (0.2.0 → 0.2.1) should be safe
- API is not yet stable
- Breaking changes can happen more frequently

**Current UiPath SDK:** Version 0.x (pre-1.0)

## Version Constraints in requirements.txt

### Exact Version

```txt
uipath==0.2.0
```

**Use when:**
- Need exact reproducibility
- Testing specific version
- Known issues with other versions

**Downside:** No automatic bug fixes

---

## Version Constraints (Continued)

### Minimum Version

```txt
uipath>=0.2.0
```

**Use when:**
- Need features from 0.2.0+
- Want automatic updates
- Trust package maintainers

**Downside:** May get breaking changes

---

## Version Constraints (Continued)

### Version Range (Recommended)

```txt
uipath>=0.2.0,<1.0.0
```

**Use when:**
- Need features from 0.2.0+
- Want bug fixes and new features
- Want to avoid breaking changes

**Best Practice:** Most common in production

---

## Version Constraints (Continued)

### Compatible Release (~=)

```txt
uipath~=0.2.0
```

**Equivalent to:** `>=0.2.0,<0.3.0`

**Use when:**
- Want patch updates only
- Don't want new features
- Maximum stability

---

## Version Constraint Examples

```txt
# Exact version
uipath==0.2.0

# Minimum version
uipath>=0.2.0

# Maximum version (not recommended alone)
uipath<1.0.0

# Range (recommended)
uipath>=0.2.0,<1.0.0

# Compatible release
uipath~=0.2.0

# Complex range
uipath>=0.2.0,<1.0.0,!=0.2.3
```

## Handling Breaking Changes

### Common Breaking Changes

1. **API Signature Changes**
   - Function parameters modified
   - Return types changed

2. **Module Reorganization**
   - Import paths changed
   - Modules renamed or moved

3. **Deprecated Features Removed**
   - Previously deprecated code removed
   - Need to use new API

---

## Handling Breaking Changes (Continued)

### Example: Function Signature Change

**Old API (0.1.x):**
```python
from uipath.orchestrator import start_job

result = start_job(release_key, robot_id)
```

**New API (0.2.x):**
```python
from uipath.orchestrator import start_job

result = start_job(
    release_key=release_key,
    strategy="Specific",
    robot_ids=[robot_id]
)
```

---

## Handling Breaking Changes (Continued)

### Migration Strategy

1. **Create a feature branch**
   ```bash
   git checkout -b upgrade-sdk-0.2.0
   ```

2. **Upgrade SDK in isolated environment**
   ```bash
   pip install --upgrade uipath
   ```

3. **Run tests and fix failures**
   ```bash
   pytest  # Identify failures
   # Fix code
   pytest  # Verify fixes
   ```

4. **Update requirements.txt**
   ```txt
   uipath>=0.2.0,<1.0.0
   ```

5. **Merge after thorough testing**

## Pre-Release Versions

### Version Suffixes

- **alpha** (`0.3.0a1`): Early testing, unstable
- **beta** (`0.3.0b1`): Feature-complete, testing phase
- **rc** (`0.3.0rc1`): Release candidate, near-final

### Installing Pre-Release

```bash
# Include pre-release versions
pip install --pre uipath

# Specific pre-release
pip install uipath==0.3.0rc1
```

**Warning:** Not recommended for production

## Lock Files for Reproducibility

### Problem: Transitive Dependencies

```txt
# requirements.txt
uipath>=0.2.0,<1.0.0
```

**Installs:**
- `uipath 0.2.0`
- Plus dependencies: `httpx`, `pydantic`, `click`, etc.
- Dependency versions may vary over time

---

## Lock Files (Continued)

### Solution: Lock File

**Generate lock file:**
```bash
pip freeze > requirements-lock.txt
```

**requirements-lock.txt:**
```txt
uipath==0.2.0
httpx==0.25.0
pydantic==2.4.2
click==8.1.7
...all dependencies with exact versions...
```

**Install from lock file:**
```bash
pip install -r requirements-lock.txt
```

---

## Lock Files with uv

### Generate Lock File

```bash
# Create requirements.in
echo "uipath>=0.2.0,<1.0.0" > requirements.in

# Compile to lock file
uv pip compile requirements.in -o requirements.txt
```

### Install from Lock File

```bash
uv pip sync requirements.txt
```

**Advantage:** Resolves dependency conflicts optimally

## Common Issues and Solutions

### Issue 1: Version Conflict

**Error:**
```
ERROR: Cannot install uipath because these package versions have conflicting dependencies
```

**Solution:**
```bash
# Check conflicting packages
pip check

# Upgrade pip and setuptools
pip install --upgrade pip setuptools

# Try installing again
pip install uipath
```

---

## Common Issues (Continued)

### Issue 2: Cached Old Version

**Problem:** pip install doesn't upgrade

**Solution:**
```bash
# Clear pip cache
pip cache purge

# Force reinstall
pip install --upgrade --force-reinstall uipath
```

---

## Common Issues (Continued)

### Issue 3: Multiple Python Environments

**Problem:** Wrong Python/pip version

```bash
python --version   # Python 3.11
pip --version      # pip from Python 3.8
```

**Solution:**
```bash
# Use python -m pip to ensure correct pip
python -m pip install --upgrade uipath

# Or use python3
python3 -m pip install --upgrade uipath
```

## Hands-On Exercise

### Task: Version Management

1. Check your current SDK version (3 methods)
2. Create a requirements.txt with version range constraint
3. Generate a lock file
4. Simulate an upgrade (if available)
5. Create a version compatibility check script

**Time:** 20 minutes

---

## Exercise Solution

```bash
# 1. Check version
uipath --version
python -c "import uipath; print(uipath.__version__)"
pip show uipath

# 2. Create requirements.txt
echo "uipath>=0.2.0,<1.0.0" > requirements.txt

# 3. Generate lock file
pip freeze > requirements-lock.txt

# 4. Check for updates
pip list --outdated | grep uipath

# 5. Version check script
cat > check_version.py << 'EOF'
import uipath
import sys

REQUIRED_VERSION = "0.2.0"

current = uipath.__version__
print(f"Current SDK version: {current}")

if current < REQUIRED_VERSION:
    print(f"ERROR: SDK {REQUIRED_VERSION}+ required")
    sys.exit(1)
else:
    print("✓ Version compatible")
EOF

python check_version.py
```
